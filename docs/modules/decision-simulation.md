# 星盘决策模拟

## 产品边界

纳管企业的五角色分析在每次模型请求前复核当前企业状态、套餐期限及 `decision` 功能，排队期间停用、到期或撤销功能后不再调用模型。既有报告读取不触发模型，也不因模型执行权限撤销而丢弃已返回结果。纯计算及页面请求仍由业务路由权限约束。

面向已经经营企业的老板。主模式从同一真实经营基线比较维持现状与备选方案；创业型评估、模拟、计划、单公司回放作为独立模式完整承接。界面使用Shensi现有黑绿体系，不迁入原Next.js前端。

第一阶段外生因素为订单需求、采购成本、回款时间、交付效率。各方案共享预先生成的样本×月份×因素路径；经营策略不消耗外生随机流。参数有历史依据则注明来源，没有则标明可调假设，不把默认参数描述为企业历史数据。重大政策和战争不在首版。实际执行反馈采用独立的人工录入复盘，不自动改写模拟规则。

## 当前代码

`backend/src/decision-simulation-engine.ts`是独立、无网络/数据库副作用的经营模式核心。公开输入、保存结果与回放合同位于`contracts/openapi/decision-simulation.v1.yaml`，前端使用生成类型。

- `generateOperatingPaths`：显式seed、1–1000样本、1–24月。四因素有界扰动；persistence/commonWeight为凸组合权重，不冒充从数据估计的相关系数。共同不利扰动降低需求/交付、提高成本/延迟。保存完整路径与模型版本才构成跨版本回放依据，只有seed不足以承诺升级后相同结果。
- `simulateOperatingPlans`：所有方案读取相同基线和路径，输入不原地修改。单价/直接成本按交付计，交付生成应收，到期才计现金收入；原有应收应付按已给到期月结算。交付限制形成积压，不产生虚构收入。金额使用整数minor并校验安全整数。
- 成本边界：直接成本在交付月支付，固定费用按月；暂不模型化原料库存、采购预付款、融资、税、折旧。期初积压按基线单价结算。负现金表示未获融资的资金缺口，不自动注资。现金最低点指期初与各月末，不保证覆盖月内支付峰值；利润为本模型经营贡献扣固定费用，不是法定净利润。

`backend/src/decision-simulation-analysis.ts`：自动加入维持现状，保留完整月度回放，输出样本利润范围、最差月末现金、缺口/积压样本数及逐样本方案差值。范围只覆盖当前样本，不代表置信区间或现实成功率。

敏感性是条件性单因素扰动：需求/成本/交付±10%，回款±1月，限制在模型有效域；其余已实现路径保持不变。因此它不是全局方差分解，也不估计相关输入的因果贡献。临界点先提供基线价格/成本不变且无随机冲击时的月经营盈亏平衡交付量，同时检查产能可达性，不称作现金盈亏平衡点。

## 实施顺序与验收

1. 已实现并有隔离测试：经营核心、同路径比较、现金/利润分离、回放、条件敏感性与基线盈亏平衡量。
2. 已接入认证/工作区及用户隔离的生成、历史列表与保存版本读取API；MySQL只新增`decision_simulation_runs`，报告正文复用加密存储，不创建第二套生产库。相同runId与输入重试读取原结果，变更输入冲突。
3. 现有前端已有独立“星盘决策模拟”入口，基线/方案输入→运行→比较→回放。原生开发实例已分别生成正常经营、回款延迟、产能受限三条明确synthetic记录。这是计算入口验收，不是上传资料完整流程或创业模式验收。
4. 增长顾问、客户目录、报价工作台、财务经营、ROI经营分析、财务委员会的前后端、路由、侧栏、任务入口、数据及共享依赖全部保留。星盘作为独立新增工作区，不替代或删除这些模块。
5. 优先完成企业资料上传→事实校对与缺失冲突→五角色实际模型分析→100条固定路径→报告导出原生验收。创业模式仍待接入，不用手填示例替代完整业务链。

## 企业资料与五角色接入状态

`decision-source-material.ts`复用独立的安全解析实例，多文件原引用加`file:N:`前缀，保留真实页/表/段落位置；输入上限10文件、总计5MiB，损坏成员整批拒绝。支持CSV、XLS、XLSX、文本PDF、DOCX。现有PDF解析器没有OCR，扫描件不可声称已解析。读取不要求三表齐全，不替换智能体中心的当前资料，不写CRM、正式财务或历史外联。

`decision-five-agents.ts`提供Founder/Market/Operations/Finance/Judge顺序协作，每个角色调用已有模型网关，后续角色读取之前的公开摘要并重新引用原始资料。角色有queued/running/completed/insufficient/failed/cancelled状态，空输出不是成功；保留真实provider/model，不输出内部推理链。`finance-document-model.ts`新增经营角色职责，原财务角色入口不变。

`decision-preparation.ts`管理按用户/工作区隔离的一小时临时资料会话；后端重启会清除未完成准备。上传只解析；用户确认校对后的输入和模型使用后，异步执行五角色并生成100样本，最终把原始引用、角色结果、输入与随机路径一起保存到加密报告。来源不足保留insufficient状态，模型调用失败不保存为整链成功。报告GET不再次请求模型。

前端已有多文件选择、合成CSV下载、来源候选/冲突/缺项校对、模型确认、角色状态、报告与全路径HTML导出。数值候选仅从明确字段和单位的单值表格行提取，多期间/模糊单位留待人工；未识别不是零，不要求补齐三表。可调波动仍是显式假设。已在原生开发应用完成一份合成CSV的上传→八项校对→五次真实DeepSeek调用→100条路径→HTML导出→历史只读重开；不是用户真实企业验收，也不是多格式混合上传的原生验收。

经营模型分析的材料包含三类引用：`file:N:`是原文件位置，`confirmed:N`是本次人工确认条件，`calc:N`是确定性规则计算。五角色最多各4项公开分析，引用经过真实材料白名单校验；不能把条件模拟当作历史事实，也不能把缺少三表重复堆为每个角色的全部结论。

## 回放界面

新生成报告保存结构化降本增效建议：`decision-operating-recommendations.ts`依据确认基线、资金缺口/积压及敏感性选择回款、采购、交付、单位贡献和需求验证事项。每项保存证据位置、行动、机制、前提/成本、优先级、负责人、周期和指标；行动效果标为待试点。采购/回款对照直接保存本次敏感性计算的基线与扰动结果，不把利润范围之差冒充逐样本因果收益。未建模库存、返工、自动化仅列需核实条件，不生成ROI或裁员建议。页面与HTML共用同一展示函数；旧记录缺字段明确未保存，不在GET时补算。

顶部四步是键盘可访问的回看导航：资料与校对、五角色、100情景、报告。资料与八项经营数据在同一个连续工作区；内部旧 `facts` 导航仍定位校对表单并归入首步。没有字段来源时不占用详情栏，来源核对只在有实际候选/缺项时显示。未就绪步骤说明前置操作，不启动任务；切换保存报告不重复GET、调用模型或计算，并保留回放情景/月/方案及未保存输入。历史五角色显示保存的证据，不模拟实时分析。运行中允许切换查看，输入临时只读；轮询及完成不会抢回用户选定步骤。输入重新编辑后明确区分草稿和保存结果，只有显式提交才生成新版本。

应收、应付、备选方案与波动假设使用中文参数表单，原 JSON 保留在默认折叠的高级区。金额输入为元，精确转换成整数分，超过两位小数拒绝而非四舍五入；月份、区间、倍率、权重按原契约校验，不更改引擎规则。编辑只替换指定字段，保留原 JSON 中的事件和其他高级字段，不承诺服务端接受未知字段。示例、历史重开和资料解析会同步表单；无效可见输入阻止提交。表单与高级 JSON 的互转测试在 `parameter-editor.test.ts`，实际页面提交测试在 `view.test.ts`。

整个工作区使用独立星空环境层（`atmosphere.ts/.css`），复用已有星尘渲染器，表单及文字不旋转。五角色画面激活时暂停外围粒子，避免两层动态竞争；离开页面卸载、后台隐藏、手动关闭或系统减少动态时停止帧，宽度不足700时保持静态星空。装饰不表示业务进度。双主题/宽窄布局、可读对比度、输入保留及动效开关的隔离验收命令为 `pnpm --dir frontend exec tsx scripts/test-decision-parameters.mts`；隔离预览先于主页面源码接入，不调用模型或真实业务服务。

已登录账号的星盘工作区在当前文档内存中按账号/工作区保留原界面：离开再返回保留文件选择、中文/高级参数、已读资料、当前步骤与回放选择，不重启读取或提交任务。已经明确启动的资料分析/保存可在离页期间完成，返回读取同一结果，界面锁随原请求释放。离页暂停粒子和回放；退出登录或身份/工作区变化销毁缓存和监听，迟到响应不能恢复界面。没有新增磁盘草稿或文件副本，应用关闭不保留未保存资料；准备资料的服务端一小时有效期不因缓存延长。

第二步进入五角色星系。实际任务沿用实时状态；历史记录标明“历史查看”，点击五个角色节点可读保存正文、模型归属和引用。没有角色结果时显示“星系预览”及待开始节点，没有启动模型。历史/空态星尘只是可关闭的氛围动效，不是未保存的执行时序回放；离开步骤后停止动效，后台轮询不会重新激活动画。

每个情景小图显示所选月份的需求变化摘要，悬停可读完整四因素；右侧显示当前因素与经营利润。下方“这些结果如何形成”读取保存的逐月shock、收付款、利润和现金，按需求→交付→收入/成本→应收回款解释，并提供逐月表和原始假设说明。百分比相对无扰动倍率1，回款延迟相对基线账期；净现金流是实际回款减支付，不是某个因素的独立贡献。对照先核验两条完整已存四因素路径是否一致，再显示现金及利润差额；缺失或不一致不称同条件效果。旧记录缺因素明确不可还原，不补员工离职、客户流失等故事。

可选日常事件编辑器提供8个模板：人员缺勤/熟练度、销售需求增减、采购单价涨跌、客户延期/恢复基准账期。显式确认适用后添加，默认关闭；可调起始月、持续期、最终倍率或延期、发生概率和假设。发生一次后持续整个时间窗，概率不是逐月概率。生效值替代背景，不重复叠加；同模板重复或同因素月份重叠拒绝。保存被替代背景、事件和最终因素，各方案共用seed事件路径。有事件配置的结果版本为`operating-monthly-v2-events`；无事件保留v1计算。旧记录只读，不补造事件。事件假设也作为confirmed材料供五角色解释。

完整覆盖、文献边界及待实现决策风格见[因素库](decision-factor-catalog.md)。坏账、额外费用、返工与动态行动规则尚未建模。决策风格须用户确认，仅通过可解释的偏好或明确行动规则参与，不能作为利润乘数或心理诊断。

可选决策偏好由用户确认后放入`input.decisionPreferences`；明确反馈仅形成待确认候选，默认不启用。`report.preferenceAssessment`保存排序依据及逐方案现金底线满足状态。页面和HTML展示同一快照，不改变模型路径/利润。偏好可纠正、清除本次输入、关闭候选；历史不可变报告不会因清除当前偏好被改写。

## 跨会话个人档案与执行复盘

实现由`agent-operating-memory.ts`统一拥有，`decision-memory.ts`保留兼容导出。智能体中心和星盘共用`/api/v1/agent-memory/operating`、个人修订号和前端面板；旧memory入口继续兼容。中心只在明确选用后把经营取舍用于文字问答，不用于获客或语音。中心可复盘原星盘保存建议，尚未把聊天建议转成独立复盘对象。详见[共享能力](shared-agent-capabilities.md)。

校对页的“我的长期偏好与复盘”显式保存已确认偏好。读取不自动应用；“用于本次输入”才复制到草稿，新报告保留当时快照。支持纠正、关闭长期偏好、单独关闭反馈学习、删除偏好和JSON导出。删除只清除个人偏好和待确认候选；原有复盘及历史报告快照保留，目前没有单独删除历史报告的接口。企业共享事实/SOP仍走现有资料路径，与个人偏好分开；这里的文字不升级成系统指令、不自动送模型。

报告下方“执行与复盘”关联本人保存报告内真实存在的建议。先认领保存行动、指标、单位、基线、目标、复盘日期和来源，再录入实际值、观察日期、来源及归因不确定性。录入时间由服务器生成。实际结果只能与已存同指标计划对比，不能在录入结果时改目标；差额不是因果收益，不伪造建议中没有的数值预测。手填复盘不创建CRM业务、不完成advisor业务回执。

仅在长期档案启用且允许学习时，复盘的明确cash/profit/delivery反馈生成待确认候选；单独点击确认才更新长期偏好。关闭/删除清除待确认候选；重新启用或修改结果说明不会重新生成已采用/清除的相同候选。任何修改均以修订号CAS防止并发覆盖。刷新个人信息不授权旧复盘表单覆盖新版本；需要明确“刷新复盘（放弃未保存编辑）”。保存某条建议保留其他卡片未保存编辑。

`agent-operating-memory.ts`、`decision-memory-repository.ts`、`decision-memory-router.ts`提供该边界。`decision_personal_memory`按actor/workspace一行加密聚合，复用AES-GCM身份绑定；偏好、关闭学习与候选写入共享CAS，删除保留修订号避免旧页面复活数据。上限200条复盘，达到上限返回明确错误，已有记录可更新、完整导出，不截断导出。无新依赖、图数据库、训练或外部集成。个性化规则自动推断仍未实现。

星盘采用蓝白/黑绿同构框架、四步导航和连续宇宙背景。`assets/galaxy-cosmos-blue.png`是无文字的独立栅格资产，保留三角三臂、中央旋涡及上/左下/右下三星核的宝蓝冰蓝造型；`cosmos.css`只作用于星盘，不更改全局导航。资料与校对、情景和报告保留各自真实业务内容，背景不携带角色节点或分析侧栏。第二步始终展示经营负责人、市场、运营、财务、综合复核五个可键盘操作的节点：无结果时标为待开始，点击只展示职责，不请求模型；隐藏百分比和结果计数。财务节点在上方，实际状态与历史保存结果沿用同一读取路径，历史不重新调用模型。

星尘使用三层低幅漂移、三臂流光、微幅核心呼吸和三个轨道光点。宽屏指针只为粒子提供最多6px/4px的平滑视差，触屏不启用视差。五角色页的栅格背景另有18秒交替的缓慢平移和呼吸缩放（水平±0.45%、垂直±0.25%、缩放1.025–1.045），不旋转；文字和五个节点不随底图移动。仅现有`data-motion=running`状态运行背景CSS动画，不新增逐帧JS或请求。手动减少动态、系统减少动态、后台、切换步骤及离页会停止；销毁后的迟到激活不恢复动效。纯装饰不推进业务任务。

专项命令覆盖空态五节点/职责、真实结果读取和帧取消；双主题1440/390浏览器验收分别读取底图变换及节点坐标，验证底图变化、节点固定、暂停冻结、系统减少动态、切换与重复进入不增加动画实例。星尘画布跨帧变化不能替代底图动效验收。

右侧完成数量与百分比仅来自五角色快照，底部显示保存观察条数和去重后的真实来源引用数，不复制概念图的机会、风险、建议数字。无正文时查看依据按钮禁用；点击有结果的按钮打开首个带正文角色的现有证据详情。背景及星尘不推进业务进度；手动减少动态控制在星系预览也可操作，系统减少动态、后台与离页取消动画帧。宽窄布局与文件会话保留复用原控制器，没有新增接口、数据表、自动提交或外发行为。

`replay-data.ts`只映射保存的月度结果，所有方案与月份共用纵轴，当前月现金不足与全路径资金缺口统计分开。`replay-view.ts`提供100编号情景选择、月末现金轨迹、同情景对照、月份拖动、播放/暂停和速度；默认暂停，播放不会调用模型或重新生成样本。页面隐藏/离开时停止计时，减少动态效果偏好保留静态与逐月操作。

资料/校对和结果/回放分成两个工作区，历史重开直接进入保存结果，不把长表单堆在报告上方。五角色展开项保留来源和真实模型归属。视觉概念与验收规则见`docs/design/decision-simulation/implementation-spec.md`。100情景可视化、原生视觉对照与混合文件整链验收继续推进，创业模式待接入；六个现有Growth/财务模块全部保留，不属于删除待办。
