## 实际入口

| 入口 | 源码 | 消费者与批量语义 |
| --- | --- | --- |
| 财务经营、ROI、委员会通用资料 | `frontend/src/growth/finance/enterprise-analysis.ts` | 只读解析，成功文件集合交给当前模型；逐文件原文引用、合并报告、同集合转智能体 |
| 财务结构化入账 | `frontend/src/growth/finance/view.ts`、`growth/runtime.ts` | 各文件独立映射、预览及明确提交，不跨用途合并事务 |
| 智能体正式三表准备 | `frontend/src/growth/agents/view.ts`、`controller.ts`、`real-controller.ts` | 每个正式package只能有对应表种各一份；多文件先暂存候选，用户明确选择对应表种，不自动覆盖同种报表 |
| 智能体聊天附件 | `frontend/src/growth/agents/chat-attachments.ts`、`cfo-conversation.ts` | 选择/拖入最多10份5MB，按当前角色与会话保存只读集合；上传零模型调用，发送文字问题才使用，移除/清除解除旧引用 |
| 持久参考知识库 | `frontend/src/knowledge/`、`backend/src/knowledge/` | 独立`#knowledge`页，最多同时选10份、每份50MiB；正常账号原始字节上传、加密原件、持久版本/解析/索引，按本人workspace＋actor和角色检索 |
| 历史双报表演示界面 | 同上view/controller的legacy分支 | 当前真实智能体不用该入口；演示分支明确不执行真实上传，不将它当成产品验收成功 |

检索覆盖 input[type=file]、动态input.type、FileList、drag/drop、showOpenDialog、showOpenFilePicker、上传API和真实调用方。
知识库具有独立元数据和二进制上传接口，不复用临时附件预算。当前未发现头像、产品图片或新的桌面原生上传接口；PDF保存为导出，不是上传。

知识库资料不因解析完成而成为公司已核实事实；只有启用且可检索的有效版本参与文字问答。
书籍、文件和内部资料保持来源/物理页或表格坐标及待核对标记，向当前模型仅发送相关片段。

## 实施与验证

聊天附件与财务来源分开保存，不进入知识库、CRM或正式报表。跨页保留内存文件和解析状态，角色切换不串资料；新对话清空当前角色附件，退出登录或切换身份清除全部附件。解析结果有效一小时，过期需重新解析。该入口当前按整个集合解析，损坏成员导致集合不可发送，用户可移除该文件后重新解析；不是逐文件成功集合自动筛选。文字附件不自动进入语音。

聊天文字视图由 `cfo-session-view.ts` 在当前Renderer内按身份及角色持有，普通切页不再销毁消息、引用、草稿或进行中的文字请求；返回不重复发送。新对话清空当前角色消息和附件，其他角色不受影响；退出或身份变化中止并清理。这不是关闭应用后的文件或专项聊天历史恢复。

关闭原生文件选择器返回窗口时，授权刷新若仅改变检查时间，不广播身份变化、不销毁当前角色对话；账号、工作区、权限或授权状态变化仍通知消费者并重新校验。只读资料回答保留各观察的有效来源坐标，并附文件名映射，多文件的`file:N:`前缀不丢失；4000字符总限额仍生效，不截断依据。来源是可追溯原格，不代表审计验证，也不允许模型补造缺失金额。

2026-09-25原生开发实例合成验收：财务角色上传单份CSV成功，实际deepseek-v4-flash准确读取12000收入、3500及2000支出，并明确运费缺失不可按零处理，没有要求三表。受限于只读模型不计算新数值，未给出已知净额小计；此项不声称通过。追加XLSX后两附件跨页返回仍保留在财务角色，未串到经营总管。首次联合模型调用返回MODEL_PROVIDER_UNAVAILABLE；修复后在64717源码实例复测成功（模型账本06:18:20 UTC，11162ms），回复显示逐观察原格引用、实际与预计区分，以及file:1流水/file:2计划的文件映射。两次文件选择器返回均保持财务角色，未复现默认CFO回退。长回复滚轮在原生窗口未能滚动，点击输入区可到结尾、点击回复可到开头；中段5000/1800及运费完整措辞尚未全部目视核对，不把联合金额质量算全部通过。此为合成附件功能检查，不是真实客户企业质量验收。

授权刷新/角色归属及来源服务专项、真实运行时六角色PDF/DOCX/零散资料契约验证通过；完整测试、构建、桌面Renderer构建、context、diff通过（`job-mugkfbsk-d851d614`）。长回复滚动的内层overscroll拦截与inspector占列冲突已修正，901–999px侧栏下排；双主题五宽度滚轮上下、PageDown和输入可达回归通过。49867原生实例用已保存CFO回答只读验证双主题宽/窄窗头中尾连续阅读，不调用模型。接续时应用已切到获客页，返回财务角色仅附件保留，原临时回答已清空；故原联合回答中段金额仍未核验，不用替代历史回答作金额质量证据。没有放宽金额校验或新增业务入账。

通用资料每批最多10份、合计5MB，串行读取并逐份显示状态，支持移除/失败重试/成功集合勾选。选择器及拖放追加资料；同名、同大小、同修改时间及同类型的重复选择不再次加入。识别或分析进行中须先完成或停止，才能追加。一份失败不取消其他预览；改变资料集合使旧报告失效。分析请求由第一份与additionalFiles组成，后端返回逐文件metadata与file前缀引用；同一个documentId对应整个选中集合。报告和智能体沿用该集合。原单文件请求仍兼容。

通用资料组件由当前Renderer会话持有，按账号、工作区及分析用途隔离；普通路由离开仅卸载视图，文件、状态与进行中的请求继续保留，返回不重复调用模型。退出登录、切换工作区和权限变化销毁相应会话并中止请求。关闭应用后不恢复文件内容；不写localStorage或磁盘缓存。这不改变下方结构化入账队列的生命周期。

财务入账多选及拖放保留逐文件队列；打开一项进入现有用途、映射、预览和明确提交流程。未选择的文件不自动提交；现有服务继续按工作区、文件hash、sheet、行号及业务区分符生成稳定行身份，并执行既有幂等命令。同批文件不会合并不同用途事务。

正式三表每种可暂存多份候选，但正式package只允许每种各一份；多份候选复用只读服务串行识别，逐项显示成功/失败与原因、支持移除和重试。多选不会默认选第一份或最后一份，用户明确选用后才进入现有package预览与确认流程。更换候选使旧package预览失效。历史演示不变更为真实上传。

自动回归覆盖混合CSV/PDF/DOCX集合、文件前缀引用隔离、解析失败不请求模型、前端多文件拖放/部分失败/重试/移除/迟到响应、正式同种候选必须明确选用；XLS支持沿用前轮回归。源码58328原生多选CSV/XLS/损坏XLS，显示两成功一失败，模型仅使用两成功文件并返回双文件引用；首次输出未过校验，手动重试完成。PDF保存到 `/tmp/shensi-batch-acceptance/batch-report.pdf`（409068字节），转智能体来源显示两份文件，未发送追问。

源码58816原生三表多选有效/损坏XLS，逐项显示识别成功及格式错误，正式选择保持0/3；明确选用有效文件后为1/3。实测发现选用会清除其他失败提示，已收窄为只重置旧选用项并补回归，前端全集通过。结构化入账队列由代码与回归核对，未执行真实入账；ROI与委员会复用同一资料组件，本次原生多选在财务经营完成。最新源码开发版59110，无新安装包。
