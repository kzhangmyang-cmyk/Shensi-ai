# 账号运营后台实施计划

目标：交付独立运营后台的企业客户、账号、套餐授权、操作日志四页，保持客户业务与现有数据不变。
依据：[已核查方案](account-admin-launch-readiness.md)。用户已授权实现；采用当前任务内顺序开发，最后独立复核。进度只记录在 `../PROJECT_STATUS.md`。

## 约束

- 所有验证写入使用隔离合成数据；不发布、不购买资源、不迁移真实库、不操作既有外联队列。
- 不复制用户表；用户修改、审计及内存回滚共用现有串行持久化边界，保留API单实例锁。
- 套餐trial/basic/pro先配置为未发布；没有明确商业规则不向已有企业授予或撤销权益。
- 平台权限与客户角色隔离；后端强制校验，前端类型由contracts生成。
- 不修改首页素材、字号和星盘行为；文档与测试随增量同步。

## 实施顺序

1. 修复 `desktop/tests/enterprise-local-browser.test.ts` 的联合类型收窄，运行桌面类型检查和相关测试。
2. 抽取账号命令服务：规范登录名/角色、ID唯一性、持久化失败回滚、停用/恢复撤销会话、追加审计。接入旧accounts路由以避免旁路。测试并发、重复账号、写失败、越权和自停用。
3. 实现平台身份、企业目录与版本化套餐存储、事务命令、运营会话/MFA；保持所有真实账号未纳管状态。测试企业隔离、最后所有者保护、恢复码单次消费与权限失效。
4. 建立独立OpenAPI并生成前端类型；接入API与任务/执行端授权检查，纳管企业失败时不放行，未纳管企业保持现状。测试到期边界、冻结排队、迟到响应和幂等续期。
5. 新增独立运营入口与四页界面，完成加载/空态/失败/冲突反馈，使用隔离合成服务做创建→授权→停用→恢复→到期→续期验收。
6. 同步模块README、API索引、部署及迁移文档，执行context、根test/build、desktop类型检查、diff检查；记录源码验收与剩余发布阻断，准备境外单实例维护窗口部署及阿里云恢复/回退验证步骤。

## 首增量交付边界

上面的顺序覆盖完整目标，不代表每一项已经实现。当前实现以
`../modules/platform-administration.md` 为准：一次性客户改密、运营成员管理、
MFA恢复、老客户纳管、成员创建和完整审计导出仍在上线清单。并发控制使用
revision拒绝重复旧写，尚无幂等结果重放。真实发布/迁移需独立环境验收。

## 复核重点

持久失败不得留下内存权限变更；套餐变更不可扩大业务归属；未配置套餐不得发布；停用恢复不可复活旧token；迁移前后密钥和不可撤回的外部动作不得丢失或重复执行。
