# 六角色真实模型兼容性验收

日期：2026-09-25。目标为真实模型普通聊天和公开检索链路，不是财务意见准确率评测。

## 环境与范围

- Electron 源码开发实例，新增四角色最终入口 `http://127.0.0.1:60053/#agents`，Backend5638；这是当次运行地址，不是固定发布链接。
- 现有已授权 deepseek-v4-flash，经生产规划、角色回答、DDGS公开检索和引用校验；没有新增供应商。
- 使用 Computer Use 操作实际桌面窗口，检查 AX 回答、可展开来源和截图。未另开浏览器测试登录态，未读取浏览器凭据。
- 无聊天附件、无已导入报表。普通问题为“你好，请用一句话介绍你作为…顾问能帮我做什么。”
- 财务、利润、成本联网问题为“请联网查询企业…分析的公开通用方法，简要说明并列出来源，不分析任何公司数据。”
- 税务联网问题为“请联网查询中国企业税务风险管理的公开通用指引，简要说明并列出来源，不判断任何企业的具体纳税义务。”
- 本轮四角色共9次提交（财务联网修复前后各一次）；没有重复已有经营总管、现金流验收。模型自身结构修正是现有有界机制，不手动循环重试。
- 原有60秒模型请求期限、20秒公开搜索期限和停止按钮保留。外发关闭、旧抖音队列暂停、XHS模块关闭，受控重启前后队列计数相同。没有业务schema迁移或新安装包。

## 发现与修复

财务联网首轮可稳定执行请求并正常返回，但内容称“不能实时联网检索”，没有引用。账本显示规划和回答都成功；生产代码中 `not_needed` 直接返回无检索分支。原规划提示规定“一般知识返回not_needed”，未规定用户明确联网请求与该捷径的优先级。

最小改动为规划提示明确：用户要求联网、搜索或核实公开来源时，一般知识也应选择search；仍由模型抽取公开主题，私有内容/指代不清需澄清。未直接把原始问题发送搜索服务，未跳过原隐私检查。出站规划请求契约断言先失败；修改后14项规划/隐私/网关测试通过。加载新版后原问题实际返回4条引用，财务其他生产逻辑未变。

利润首轮结构错误由已有一次修正流程恢复。仅有安全的schema_shape分类，没有原始模型输出的逐字段证据，因此不猜测具体坏字段，也不新增重试或放宽校验。

## 验收边界

收尾检查：14项规划/隐私/网关专项、根test/build、context和diff均通过（`job-mugihlq9-f453d8b6`）。Vite既有大包提示仍为非阻断警告。

页面身份、非空内容、角色切换、实际回答和引用展开均已核对，原生截图无框架报错覆盖。本轮不是布局改动，不重复双主题/移动布局门禁；原双主题36角色布局记录保留。未单独采集Renderer console，因此不声称全量console无错误。

引用证明返回了本次搜索摘要来源，不证明逐页阅读全文、搜索排名质量或法律文本当前有效性。真实附件问答、所有模型厂商、长对话稳定性不由本轮公开问题覆盖。

物理麦克风、男声实际听感、连续说话和弱网听说仍需用户参与；合成WebSocket断连测试已单独完成。真实小红书/抖音账号登录与平台评论/私信不在本轮范围，不启用发送开关。
