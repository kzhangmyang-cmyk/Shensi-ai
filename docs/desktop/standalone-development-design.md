# 单机开发版设计

日期：2026-09-30。状态：用户已授权本方案设计与实施，模型 API 由客户自行配置；不是已实现或已验收声明。MySQL 随客户包再分发的授权路径尚未确认，不在此授权范围内购买许可证或公开源码。

## 目标与范围

客户安装后无需开发者电脑、云业务 API、Docker、外部 Node/Python 环境即可启动。沿用最新前后端和 MySQL 业务模型，保留全部现有模块；联网 AI、企业数据源、抖音仍依赖客户网络及其本人配置/登录。本轮交付开发安装包，不发布生产，不推送源码。

优先交付实测的 macOS arm64，Windows x64 单独构建验收。没有对应环境时不宣称 Windows 或 Mac Intel 可用。四模块报告增强和平台既有缺陷按真实验收记录，不因单机打包自动认定完成。

## 方案选择

采用原生独立 MySQL 进程＋现有 Node 业务后端＋Electron＋Python 浏览器 Sidecar。复用现有 SQL、事务和服务，不改成内存或 SQLite，不要求客户装容器。

SQLite 的部署体积更小，但本仓库的事务、MySQL repositories 和 schema 改写范围大；容器方案可复用开发脚本，但不满足免装 Docker。原生 MySQL 增加包体与生命周期管理，代价明确而业务改动最小。

## 组件与启动

打包配置通过 `SHENSI_DESKTOP_MODE=standalone` 生成仅含 `mode` 的配置，不写入远程地址；混用 `SHENSI_REMOTE_ORIGIN` 时拒绝。release仍要求Developer ID与notarytool配置。macOS内部App已携带后端/Node/MySQL并完成受限验收，产物及边界见[单机内部验收](standalone-internal-acceptance.md)；正式可再现发行配置、许可、签名及目标机验收不能由内部包替代，现有包检查的数据库限制不应直接删除。

后端应用文件通过 `backend/package.json` 的 `files: ["dist"]` 限定，生产依赖使用锁定版本pnpm的独立deploy目录；不能直接复制整个backend工作目录。运行合同目录另取 `contracts/openapi`、`json-schema` 与 `releases`，Node二进制携带其原始LICENSE。暂存后必须检查依赖符号链接不逃逸，并在脱离仓库的目录验证真实数据库/API链路；尚未验收的暂存目录不直接进入客户包。

首次客户账号使用独立 `workspace_` 工作区和 `admin` 角色，沿用普通注册的业务权限范围，不使用云平台 `super_admin/all` 身份。桌面首次设置通过 Main 专用 `SHENSI_LOCAL_INITIAL_ACCOUNT=true` 将此意图传给后端；仅空库初始化读取该值，已有账号与工作区不迁移、不覆盖。未设置此值的服务器初始化保持原超级管理员规则。

Electron Main 的本地运行管理器是唯一服务所有者：

1. 获取单实例锁；确定单机专用用户数据目录，拒绝复用 Trial、开发库和旧 packaged-local 目录。
2. 校验随包 Node、MySQL、Sidecar、Chromium 的平台/架构、固定版本与资源完整性；缺失直接显示可理解错误，不回退到开发机服务。
3. 首次启动仅在全新目录初始化 MySQL、独立数据库和最小业务账号，生成每安装独立密钥。初始化失败标记未完成，禁止把半初始化目录当作健康库或直接删除重建。
4. macOS MySQL 仅监听独立 0700 短临时目录内的 Unix socket，关闭 TCP/MySQL X 监听，使用每安装随机凭据；自有进程退出后清理 socket 目录。持久数据放用户目录，程序资源保持只读；不能将长用户数据路径直接用作 macOS socket 路径。Windows 的本地连接与访问控制需独立实现和验证。
5. 启动现有后端的编译产物，显式指定本地数据库、独立密钥、环境变量白名单、禁止读取仓库 dotenv、禁止演示种子和外发。凭据不经命令行传递或日志回显。
6. 后端健康检查确认 MySQL 持久化和预期构建身份后，再启动现有桌面代理/前端及需要的 Sidecar。随机本地端口由运行管理器传递，不硬编码开发者端口。
7. 本地端口不是授权依据；复用登录/CSRF/Origin校验并限制本地服务会话访问，不开放局域网。

后端进程使用随包专用 Node 运行时；不依赖客户 PATH 中的 Node。保留远程模式，但单机模式明确区分配置和数据路径，不把 localhost 自动当作测试版。

## 首次账号与模块授权

首次通过本机设置向导由客户创建自己的账号密码与本地工作区。单机专用初始化在全新库、回环服务和一次性初始化能力验证下执行，明确授予本机模块使用权限；不能卡在现有云端注册的“等待运营开通”。

不内置默认共享密码、不复制开发管理员、不全局放宽云端注册/套餐门禁。已初始化后关闭初始化入口；重启继续使用同一账号和数据。

## 生命周期与数据

- 启动失败：停止本次拥有的服务，保留数据与脱敏诊断；不终止客户自己的 MySQL 或浏览器。
- 退出：停止接收新任务，按 Sidecar/业务后台任务/后端/MySQL 的依赖顺序优雅关闭，超时仅处理可验证属于本应用的进程。正常退出不得丢失已确认写入。
- 异常退出：下一次启动检查真实进程归属、数据库恢复和状态；不根据旧 PID 文件盲杀，不自动重放未知外发。
- 升级：版本检查、升级前备份、迁移失败保留原数据并停止启动；不得删除数据库解决错误。不迁移本开发机业务库。
- 模型凭据与本地密钥仅存客户数据目录的受保护存储；Windows 使用适合当前用户的访问控制，不把 POSIX 0600 检查简单去掉。
- 卸载应用与删除业务数据分离，客户资料默认保留。

## 模块验收矩阵

所有项目均需在新单机运行环境复验；之前开发实例测试不替代本次。

| 模块 | 必验链路 | 外部条件/限制 |
| --- | --- | --- |
| 账号与工作区 | 首次创建、登录、重启、身份隔离、初始化入口关闭 | 不等待云运营开通 |
| CRM/私域/待办 | 新建合成客户、跟进、任务、重启读取 | 不发客户消息 |
| 企业查询 | 真实数据源连接、结果/错误显示 | 联网及所选数据源权限 |
| 获客 | 本人扫码、登录保持、只读采集、候选证据保存 | 人工扫码；旧队列不恢复 |
| 社媒 | 草稿、审批界面、关闭发送时的明确状态 | 不以模拟发送声称真实发送成功 |
| 六角色智能体 | 客户配置模型、真实问答、搜索来源、会话 | API权限/额度；仅授权合成资料 |
| 财务/ROI/委员会 | 合成资料解析、真实分析、保存/导出/重开 | 现有资料条件与缺失数据规则保留 |
| 星盘 | 假设确认、真实模型角色、计算、报告重开 | 单机不补造尚缺功能 |
| 产品/报价/增长顾问 | 合成产品和报价、状态变更、保存重开 | 不触发真实外联 |
| 设置与运营模块 | 配置持久化、权限、错误反馈 | 云运营能力不得伪装成本机已连云 |
| 小红书/其他渠道 | 关闭状态与依赖提示 | 保持当前关闭；不算平台真实验收通过 |

每项记录通过、失败、未测和具体原因。存在关键链路失败时，不标记“全部模块可用”。

## 打包与验收门槛

仅白名单加入编译代码、依赖、空库初始化资源及对应平台运行时；不包含数据库、Cookie、浏览器 Profile、dotenv、日志、真实上传文件和开发机配置。
原有打包策略禁止 mysqld；新增的单机资源白名单必须独立、限定已核验的 MySQL 发行目录，不能直接关闭资源扫描。
锁定 MySQL 分发来源、版本、架构及再分发许可证/通知要求；核对完成前不发安装包。

2026-09-30 已核对 [Oracle MySQL OEM 授权说明](https://www.mysql.com/about/legal/licensing/oem/)：官方将组合分发专有软件与 MySQL、且不按 GPL 分发相应源码的情况列入商业授权要求。此处记录的是官方分发政策，不是对本项目法律性质的最终判断。不得据“单机”“免费试用”推定免除分发义务；需要确定适用授权后再交付含 MySQL 的客户包。本地隔离研发验证与对客户再分发分开记录。

本机可测试：启动/失败/退出编排、配置隔离、初始化与持久化、资源排除、Mac 原生安装启动。
Windows 必须使用 Windows 环境构建 PyInstaller Sidecar，并验证权限、Node/Python握手、进程退出、安装卸载；Mac 单测不能替代。

根测试/构建、桌面类型检查、context、diff及新专项都要通过。最终交付路径、大小、版本/架构、SHA256、签名/公证状态及验收记录；未签名开发包明确说明系统提示，不要求用户全局关闭系统保护。

## 实施边界

第一步先验证隔离原生 MySQL 初始化和现有后端真实读写，再接 Main 生命周期及首次账号，最后接前端与完整包；避免先产出只能打开空壳的安装包。
预计修改集中在 desktop 的运行配置/启动管理/打包资源、后端单机初始化和运行配置、现有数据库初始化复用及对应测试文档；不重写获客业务核心或恢复发送开关。

日常源码开发入口`desktop:local`与原生standalone内部App是不同运行路径。后者通过`runtime-config.ts`解析standalone配置，由`prepare-local-application.ts`初始化受保护凭据并启动本地MySQL及后端，不依赖客户手装MySQL或Docker。内存Store不能替代持久化数据库；内部验收通过范围及发行缺口以当前状态与验收矩阵为准。
