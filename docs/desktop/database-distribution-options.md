# 单机数据库交付路径核查

2026-09-30；只读许可/依赖调查，不是法律意见或授权证明。

## 已确认事实

- 根 `LICENSE` 与 `frontend/LICENSE` 标注 Mulan PSL v2；不能仅据 GitHub 私有属性认定本项目采用专有许可证，也不能据根 LICENSE 推定所有第三方组件已完成授权核查。
- 后端使用锁定的 `mysql2`，安装包元数据标注 MIT。业务通过数据库协议使用独立 MySQL 服务；未发现这里链接 MySQL 嵌入式 C 服务库。独立进程/协议是相关事实，不足以单独认定组合分发法律结论。
- 日常开发入口仍可使用 Docker；单机隔离验收已使用官方原生 MySQL 8.4.11 macOS arm64，无 Docker。内存存储不持久化，不能作为客户单机替代。
- Oracle OEM 页面对组合分发专有应用与 MySQL、且不按 GPL 分发的情形提出商业授权要求。根 Mulan 许可证不自动消除 MySQL 二进制自身义务。
- 当前没有已确认的 MySQL 商业再分发许可；没有购买、改变许可证或公开源码。

## 候选路径与使用成本

| 路径 | 数据库协议/业务影响 | 客户体验与平台 | 当前结论 |
| --- | --- | --- | --- |
| 随 Shensi 内置原生 MySQL | 最少业务改动 | 理想的一次安装；各 OS/架构必须有对应二进制 | 原设计；交付前明确适用许可和履约材料 |
| 客户独立从 MySQL 官网安装 | 保留 mysql2、SQL 和持久化 | Mac 官方原生包、Windows MSI/ZIP；需要客户安装/配置，可能有管理员提示 | 不由 Shensi 包再分发 MySQL，值得验证；不能称为免安装依赖的原方案 |
| 引导官方下载安装，用户确认许可 | 同上 | 首次联网、版本/签名校验、安装失败恢复；不能静默代用户接受许可 | 自动下载不当然豁免分发/组合义务，需核查后采用 |
| 客户已有兼容 MySQL 实例 | 保留协议，校验版本与 schema | 增加一次本机连接配置；不控制或关闭客户已有服务 | 只使用独立新库及最小账号，禁止拿现有库直接迁移 |
| MariaDB 等协议兼容服务 | SQL、JSON、排序规则、事务/锁仍需回归 | 两平台资源与自身许可另核查 | 未授权替换；协议相似不等于无改动替代 |
| SQLite/PostgreSQL | 需要较大 repository/schema 改造 | 可改善某些部署条件 | 不属于已选最小方案，不实施 |

客户独立安装路径不是保证“无需商业许可”的法律结论；它改变了我们实际分发的材料，仍需结合最终产品、协议连接和各依赖许可判断。若选此路径，应用管理自有后端，不能杀掉客户独立安装的全局数据库服务；完整应用拥有数据库生命周期只适用于专用自有实例。

## 与分发选择无关的进展

- Main 已注入本地服务工厂，独立数据库、后端、首次账号与退出清理经过真实原生验收。合成模型配置在完整退出重开后保留；没有执行客户密钥连通性或付费调用。具体证据以 PROJECT_STATUS 为准。
- 官方 MySQL 压缩包包含 LICENSE；暂存 Node 22.22.3 已保留 LICENSE。后端生产依赖独立暂存与真实业务读写通过，但目前没有完整安装包第三方声明清单、MySQL 对应源码交付方案或商业授权文件，因此现有材料不足以据此批准客户再分发。
- Windows 冻结入口 `node.exe` 两项分支回归和八项 Python 测试通过；Windows 实机未测。

## 需要用户决定的最小选项

客户必须只安装应用即可使用，手动安装数据库已被用户排除，不再作为推荐或验收前提。

1. 应用自动准备专用 MySQL：保留已验证 SQL 与业务接口，由应用创建私有数据目录及随机凭据并管理自有进程；不安装系统级全局服务。当前 Mac 实现已做到本机用户级初始化。随包或首次官方获取仍须确认适用许可，首次获取另有联网、完整性校验和中断恢复成本；自动下载不是规避许可的方式。
2. 保留一体安装：先确认适用的 GPL 分发履约路径，包括对应源码、许可证及第三方声明的提供安排；若组合发行涉及本项目源码义务，需要权利人明确同意并核对兼容性。不能把根 Mulan 许可证或“不盈利”视为已完成这些事项，也不能直接推定必须公开整个项目。
3. 不接受相应源码义务时：向 Oracle 确认适用商业再分发授权及范围；是否联系、采购由用户决定，本轮不购买。

此外随包 MediaCrawler 的 `services/media-crawler/LICENSE` 是 Non-Commercial Learning License 1.1，限定非商业学习研究。用户已声明非商业目的，但客户发行用途是否符合学习研究范围、所述作者许可是否覆盖修改及分发仍需核对授权范围；不据此中断本机隔离测试，也不直接认定可向客户分发。

本机可继续准备内部 Mac 测试产物、排除密钥与用户数据，并完成脱离仓库的安装启动验证；这些技术步骤不等于客户分发授权完成。

## 自动交付技术比较与推荐

| 路径 | 实际改动与风险 | 首次运行条件 |
| --- | --- | --- |
| 应用托管原生 MySQL | 最少：现有 Mac 工厂、专用库与完整业务后端已实测；仍需成品依赖、权限、签名、安装测试及许可材料 | 随包无需下载数据库；官方首次获取需要联网。用户目录模式不主动要求系统服务安装，Windows依赖和ACL需实测 |
| 改用嵌入式 SQLite | 大：本次路径搜索含58个MySQL repository相关文件（包含测试）；41个非测试TS文件命中MySQL专用锁/SQL特征。需替换GET_LOCK、FOR UPDATE、upsert、JSON及schema语义，并验证金额、时序、并发与幂等 | 数据库可随应用，无独立服务器；选择驱动后仍需两平台原生模块或运行时兼容测试 |

推荐近期保留应用托管 MySQL，不在急用阶段改写整套存储；前提是完成适用许可路径。SQLite原始代码为公共领域，但只解决数据库组件自身许可，不能代替其余依赖核查。如果MySQL授权路径无法接受，再单独批准SQLite适配项目，不用SQL字符串替换假装兼容。仓库已有存储接口可作为迁移边界，但当前memory实现不能替代持久存储。

依据：[SQLite版权](https://www.sqlite.org/copyright.html)、[MySQL数据目录初始化](https://dev.mysql.com/doc/refman/8.4/en/data-directory-initialization.html)。

法律适用边界：GPLv2第2条区别独立作品聚合与基于程序的整体作品；本项目通过mysql2与独立mysqld通信、不链接嵌入式服务库，是相关技术事实，但不能单凭进程分离判定法律归类。Oracle OEM政策要求其描述的非GPL商业组合发行取得商业协议。应让权利人/专业顾问结合实际分发包判断归类；若属于独立聚合，不应凭空要求Shensi全部源码GPL化，但MySQL自身二进制分发义务仍需履行；若属于受GPL整体义务约束的组合，则需核对整体许可兼容性及对应源码范围，或取得适用商业许可。

最小可行客户方案仍为应用自动管理专用数据库，不让客户手装：一是确认可采用GPL履约并备齐对应材料，二是确认适用商业许可。首次自动官网下载不会自动排除上述判断。用户需决定的一句话是：**你是否接受在确认适用范围后，随一体安装包履行必要的源码提供义务；若不接受，是否允许另行咨询商业再分发授权（此刻不购买）？** 未作决定前保留本机内部测试，不客户分发。

GPL条款核对自本次二进制自带LICENSE第2、3条；官方在线GNU页面本轮访问超时，不伪称在线核验成功。Oracle OEM页面本轮在线读取成功。
