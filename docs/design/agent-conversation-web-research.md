# 六角色会话按需联网

状态：交互方向已确认；本设计待审阅，尚未实施。

## 目标与边界

六角色使用现有聊天输入框提问，由后端模型判断是否需要公开检索。一般知识、只读资料摘录和纯内部计算无需搜索。删除聊天里的独立公开查询面板；搜索连接仍由设置中心管理。不增加供应商、依赖、数据库表或新的自动执行任务，不修改抖音代码和运行实例，不发送评论或私信。

## 现有链路与复用

- `financial-council-agent-center.ts` 的 `ask` 是普通问答、CFO持久会话和经营偏好问答的共同入口；选定附件进入 `FinanceDocumentService.askSelected`，其余进入 `CfoChatModel`。
- `agent-web-research-runtime.ts` 已拥有搜索连接筛选、原有供应商执行器、请求审计和角色模型路由；复用，不新建第二套搜索客户端。
- `AgentWebResearchService.run` 已清理、去重来源并验证模型引用编号；把检索与独立答案生成分离，普通聊天只使用检索部分，将公开证据交给原问答模型综合回答。
- `cfo-conversation-session-repository.ts` 对会话载荷加密保存；扩展可选来源字段，旧记录仍可读取。
- 参考 [LangGraph researcher 的来源编号和证据汇总](https://github.com/langchain-ai/langgraph-101/blob/main/agents/researcher/prompts.py) 的模式；仅借鉴边界，不引入其框架或复制代码。现有网关已支持结构化输出，移植整个研究代理会重复连接、鉴权与审计。

## 数据流

正常提问 → 当前身份/角色/附件有效性校验 → 结构化联网判断 → 可选公开搜索 → 原问答模型 → 引用校验 → 回答及来源 → 原会话保存。

1. 联网判断复用当前角色模型连接和网关。输入仅为当前问题及服务端持有的上次公开查询主题，不读取文件、财务快照、个人偏好或完整聊天历史。输出为 `not_needed`、`search` 或 `clarify`；搜索计划只包含短公开主题、必要地区和时效词，不附原问题。
2. 追问只能从同一账号、工作区、会话及角色的公开主题解析；无法确定“这个/那项”指代时询问用户，不抓取历史私有内容凑查询。持久CFO从已保存来源中恢复公开主题，其余角色沿用当前会话生命周期。
3. 搜索前独立校验计划，拒绝凭据、邮箱/电话/账号、内部金额/标识、URL查询凭证等敏感片段；不通过时停止该搜索并给出明确说明。模型指令不是敏感数据隔离的唯一防线；测试必须证明私有附件、历史记录与内部数值没有出现在供应商请求中。
4. 只从当前作用域内已启用的真实搜索连接选择，复用原有稳定顺序，每次问题最多一次检索、最多五个去重来源，无后台重试。没有连接时仍允许不需联网的问题；需检索的问题明确提示到设置中心配置，不声称已联网。
5. 搜索来源以不可信数据传入原回答模型，与内部资料分区。公开摘要不升级为企业事实，也不执行来源中的指令。文档原引用和财务确定性数字校验保持有效；不能用一个自由文本搜索答案绕过原校验。
6. 回答仅接受已有来源编号；不接受模型编造URL。供应商超时、空结果、非法引用明确为未完成检索，不默默降级成“已查证”答案。用户可以手动重试；取消/切换角色/退出阻止迟到结果展示和保存。

## 接口与持久化

扩展当前契约的回答与助手会话turn，增加可选 `research` 字段：状态、公开查询、检索供应商、检索时间、证据类型、引用编号及来源列表。来源保存标题、URL、摘要和抓取时间；旧回答无字段仍按原样展示。新的契约发布版本按仓库流程生成，禁止手写前端DTO或修改已发布快照。

来源和回答同一次会话修订号CAS保存；失败不只保存回答而丢来源。历史恢复读取快照，不再次联网。前端显示回答下方可展开来源，使用安全HTTP(S)链接与纯文本，注明搜索摘要而非全文核验；普通问答不额外显示空来源面板。语音不朗读链接，不在本次扩大为语音自动联网。

## 准确修改范围

- 后端：`agent-web-research.ts`、`agent-web-research-runtime.ts`、`financial-council-agent-center.ts`、`growth-financial-council-module.ts`，新增独立的会话联网计划模块与测试。
- 回答模型：`cfo-conversation.ts`、`finance-document-model.ts`及其服务输入类型，保留现有引用渲染校验。
- 存储：`cfo-conversation-session-repository.ts`及回归测试，无DDL迁移。
- 契约：`cfo-conversation.v1.schema.json`、`cfo-session.v1.schema.json`和相关联网schema，发布清单及生成类型。
- 前端：`cfo-conversation.ts`、`cfo-chat-messages.ts`、来源展示样式及会话恢复测试。移除独立面板挂载，不删除供应商设置。
- 文档：CFO会话、共享智能体能力、契约说明及唯一进度记录。

## 验证标准

- 六角色×普通知识/时效问题/公开主题追问；知识不搜索，时效问题只搜索一次，指代不明不猜测。
- 附件、内部金额、身份/账号凭据、完整历史不进入搜索请求；来源提示注入不能增加工具调用或改变查询。
- 同一生产资源组合覆盖普通、附件、持久会话及经营偏好四条入口；角色路由及工作区隔离不退化。
- 无连接、空结果、超时、取消、非法引用均可见且不伪造成功；失效附件仍拒绝，不借联网绕过。
- 回答+来源同事务修订保存；跨页、历史重开、退出/角色切换分别验证。旧会话无需迁移。
- 黑绿/蓝白宽窄页面检查来源展开、长标题、错误/禁用及键盘操作。
- 专项、契约漂移、根测试/构建/context/diff通过后才做精选GitHub备份与安全开发窗口同步；不打安装包。

## 成本与风险

需要判断的每次提问可能增加一次模型请求，联网再增加一次搜索；不做多轮自主研究。搜索摘要可能过时或不足，必须展示时间及证据类型。隐私测试失败为交付阻断，不以提示词承诺替代验证。新增可选来源会增加加密会话大小，继续遵守既有条数和字段上限。
