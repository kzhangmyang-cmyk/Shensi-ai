# 系统默认参考库：中央检索设计

> 中央部署方案的历史设计。2026-10-09用户明确要求服务器审核期间先随应用内置21本、六智能体默认调用；内置交付以当前README、knowledge-base模块文档、DEPLOYMENT和PROJECT_STATUS为准。本设计的中央联网/绑定/不打包限制不阻塞已授权的内置过渡版；真实服务器部署仍须后续明确安排。

日期：2026-10-08。状态：用户已确认 A（受控中央书库、跨独立安装联网使用）及中央账号绑定、owner维护、固定主题隐私与召回取舍；[实施计划](system-default-reference-library-implementation.md)已获确认。Native的D1合同/主题层、D2中央身份/一次性绑定及D3可信连接已核验完整门禁，D4独立发布存储及管理/CLI已核验18项门禁，D5有限检索正在实施；整体能力尚未接通，不是部署授权。实际证据与剩余门禁见PROJECT_STATUS，旧私有库设计继续约束现有实现。

## 1. 已确认目标

- 21本书是所有新老客户的系统默认参考库，不属于某个客户的私人知识库；不同电脑独立安装也能使用。
- 普通用户只能通过智能体回答与精确引用片段使用，不提供全文阅读、原书下载或遍历整本的接口。
- 用户自行上传的资料、报表、公司事实和历史保持原有私有边界，不随系统书库共享。
- 用户已接受中央库需要联网；这与默认关闭的“公网搜索”是两条独立功能链。
- 当前21本仍在原workspace＋actor私有库中。设计和计划工作不迁移、不复制、不重新提取、不发布这些资料。

## 2. 方案选择与复用

采用中央库：统一发布版本，各安装按题获取有限参考片段。未采用本地完整知识包，因为把完整衍生内容交给客户设备后，隐藏下载入口或加密文件都不能保证无法提取。

参考[Open WebUI的角色、能力与资源访问分层](https://docs.openwebui.com/features/authentication-access/rbac/)以及[Dify的知识库服务接口](https://github.com/langgenius/dify/blob/main/api/controllers/service_api/dataset/dataset.py)。仅借鉴边界，不引入整个平台、不复制其代码、不新增向量服务或搜索子系统；这些参考不构成对其许可证、当前安全性或生产适配的背书。若后续确需采用外部代码，另做版本、许可证、维护、安全与适配审核。

优先复用本仓库的中文词法检索、加密、版本/hash/坐标、精确引用校验，以及平台独立登录、MFA、撤销与审计。不能复用“未知workspace兼容放行”作为中央授权，也不能把当前能分页读全书的私有接口直接开放给所有客户。

## 3. 组件和身份边界

| 边界 | 职责 | 明确不做 |
| --- | --- | --- |
| 中央默认书库 | 已发布系统语料、按题检索、引用回查、撤销与预算 | 不接收客户附件、企业库或聊天历史 |
| 平台维护入口 | 受控导入、审阅质量、发布/撤回、版本审计 | 不把普通租户管理员升级为平台维护者 |
| 客户端及所属业务后端 | 正常绑定中央身份、生成通用检索主题、合并本题证据 | 不下发整本、内置管理员密钥或冒用书籍原拥有者 |
| 本人私有知识库 | 继续按workspace＋actor管理、检索与引用 | 不扩大原有SQL条件、不自动上传中央库 |

首版仅中央平台owner维护默认书库，复用MFA与操作原因/revision/审计；现有operator不自动获得书库发布权。以后委派维护者需独立权限，不附带全平台客户管理权。中央owner由控制者正常初始化，不根据“kamran”等用户名或本地管理员身份推定。

独立安装首次使用时，通过正常中央账号登录完成明确绑定；远程客户端已连接同一中央身份时复用当前合法会话。中央自行验证用户、有效成员关系、账号状态与书库资格；本地JWT、installationId或客户端自报workspace不能作为中央授权。会话绑定当前本地账号及中央主体，换号即清理；凭据仅留可信主进程/后端，不进入Renderer存储、源码、日志或安装包，不从旧Cookie/Profile提取。

默认书库不设计成高级套餐专属：所有正常开通且具备智能体执行资格的中央客户统一具备使用资格，新老客户规则相同；既有业务套餐/禁用/过期限制不被绕过。仅有本地账号的旧客户须正常中央开通/绑定，不静默上传本地用户表或数据库，也不复制密码来完成“纳管”。未绑定时明确提示，不伪造默认书库可用。

## 4. 查询隐私与回答数据流

首版采用隐私优先的**受控主题检索**：

1. 本机从问题匹配预设的通用财务主题，例如预算偏差、成本动因、现金流预测；使用固定词表和规则，不为此新增外部模型调用。
2. 中央检索请求只接受版本化词表中的主题编号、角色、词表版本和必要的认证/请求标识，主题编号最多3个；不接受任意自由文本、私有数字、文件名或用户自定义编号。中央严格校验，未知字段和编号拒绝。
3. 原始问题、公司名称、金额、附件、报表、私有片段、个人偏好和聊天历史不发送到默认书库服务。现有公网正则不是可靠脱敏器，不拿它作此边界的唯一保障。
4. 没有明确主题时不偷偷上传原问题、不另调模型改写；界面说明默认库未匹配，可由用户选择现有通用主题。主题外细分问题首版可能无命中，这是隐私方案的能力取舍，不冒充任意语义检索。
5. 中央只检索当前已发布且适用本角色的系统语料。业务后端同时按原权限读取本人私有参考，合并后总计仍最多6片段、12000字符，并区分系统、私有、公开来源；不能把两个库各自的预算叠加扩大。
6. 批准的参考片段与当前问题进入原配置的回答模型，继续区分参考方法和企业事实。默认库的隔离不意味着回答模型完全离线，也不改变原有模型提供商的数据授权。
7. 模型完成后与历史写入前分别复核中央账号资格、发布版本和片段授权，并复核本地私有资料权限。同版校验失败即明确失败，不再自动生成另一份回答。

中央会看到通用主题以及必需的账号和连接信息，不宣称“零信息外发”。默认库连接需要明确可见的独立状态；公网搜索关闭不阻断默认库，关闭知识检索则不访问默认库或私有库。语音行为不因本次设计自动改变。

## 5. 发布与引用

系统语料使用独立corpus归属、持久发布清单及不可变版本，不伪装成某真实用户。原21本的私人加密AAD不能靠修改owner列变成共享数据；未来经过单独授权的发布过程，按精确源/产物hash选择这21份，经受控读取、验证、独立加密和索引就绪后原子发布。既有提取结果复用，不重做OCR；原件、私人记录及失败证据保留。

发布清单保留源hash、衍生hash、章节、物理页、缺页及OCR/表格/公式待核对标记；67页不完整原件继续保留source_incomplete。只有完整候选通过检查才切换有效发布，失败不影响上一版。控制者须在真实发布前确认内容使用权和准确发布清单。

普通读取入口只提供本题已释放的有限片段与精确引用回查，不提供默认库原件、全文、通用chunks分页、连续翻页或任意chunk读取。引用授权绑定中央主体、本题、书库/发布版本、来源hash、chunk及允许的摘录范围；猜测标识、替换版本或跨账号复用均拒绝。来源ID须带系统/私有的明确命名空间，不能让同名K编号或本地UUID触发另一库读取。

引用点击展示本题可访问的摘录、来源和页码/质量标记，不跳转私人整书详情；普通“我的资料”只管理本人上传。服务器独立实施单题和累计释放预算、账号/设备/IP速率限制及异常审计，不能只靠按钮隐藏或让客户端自报预算。预算配置必须有上限，缺失不得无限开放；具体初值随实施计划中的容量与误拦截测试确定。

这些措施减少批量提取，但不承诺已显示文本不能被复制、跨查询不能被拼接。账号/版本撤销阻止新的读取和新的回答释放，不能收回用户已经收到的内容。已保存回答仍按原私人历史权限加密保存并标明历史引用；再次取源须复核中央授权，不能以历史快照冒充当前有效版本或自动换版。

## 6. 断网、失败与版本

- 未绑定、未配置、断网或中央故障：明确显示默认库不可用，不伪报“没有相关书籍”。本人私有检索与其他既有功能按自身权限继续；新回答明确未使用默认库，不偷偷改用公网或缓存全文。
- 查询无命中与服务不可用分别呈现。词表版本不兼容要求更新，不猜测映射、不转发原问题。
- 身份/发布在回答期间撤销、同版验证失败或确认结果不确定：不返回新引用、不写新历史，不自动重调模型。
- 401要求正常登录，403/404按授权边界处理，429明确提示；不自动换账号、扩大权限或重放已发送模型请求。账号变化清理内存证据，迟到结果不得恢复前账号片段。
- 客户端协议由正式合同定义与生成；新语料来源和连接状态采用新不可变发布，不修改已发布的Growth1.0.39字节。旧客户端不因收到新中央ID而误走本地原件/分页接口。

## 7. 验收目标（尚未执行）

1. 两套独立安装、不同中央客户正常登录，均可用已发布默认库；无需复制书籍、数据库或管理员凭据。新老账号同规则。
2. 两客户均无法读取对方私有上传、企业数据、历史；伪造本地admin、同名账号、workspace或设备ID不授予中央权限。
3. 普通客户及租户管理员均不能导入/发布/撤回系统书籍，也不能下载原件、分页遍历或越过本题引用范围；owner维护有正常MFA、revision与审计。
4. 在测试问题中放入公司名、金额、密钥样式、私有引用与历史，捕获中央检索传输，证明只含固定主题编号和必需元数据；无匹配时零检索外发，不新增模型规划调用。
5. 六角色依原批准边界各验证真实模型、同版hash/坐标/摘录/warnings与调用审计；合成测试不能替代实测，不自动重试，不重用已消耗守卫。
6. 对在途撤销、发布切换、断网、401/429、取消、账号切换、恶意语料指令、累计提取及引用猜测执行负向测试。资料不升格为系统指令、企业数字或现行法律证明。
7. 完整应用及中央/本地实际持久服务重启后，发布清单和私人历史保持一致；客户端不持有完整默认语料。双主题、宽窄屏、键盘和引用定位分别实测。
8. 根test/build/context/diff、相关真实MySQL/合同/浏览器门禁覆盖新实现；旧918项回归只证明旧代码。真正完成后才fresh独立全分支审查、可分离提交/task-done与排除资料/secret/runtime/installer的精选私有源码备份。

## 8. 设计与执行关卡

中央账号正常绑定、首版仅owner维护、固定通用主题检索及其召回限制、受限引用与明确断网降级已获人类确认。实施计划中的中央会话生命周期、正式合同、预算初值和发布事务任务已通过人类评审，按此前Native方式执行；先建立新基线，再逐项RED/GREEN，最终独立全分支审查。设计和计划都不是可直接运行的发布脚本。

真实部署是另一个明确关卡：需要控制者指定并授权生产服务/数据库/存储目的地、域名TLS、维护身份、费用和书籍发布清单。当前Render/Aiven仅属隔离测试，不能默认充作生产书库；本轮不创建云资源、不上传资料、不复制本地业务库、不安装依赖、不构建App/DMG。未满足部署关卡时只能做另行获批的本地合成实现/验收，不能声称客户已可用。

当前Task8保持未完成。此设计不恢复旧脚本登录、不消耗剩余三角色或公开联网问答授权、不删除任何一次性守卫，也不更改已有原件/提取/实际验收结果。
