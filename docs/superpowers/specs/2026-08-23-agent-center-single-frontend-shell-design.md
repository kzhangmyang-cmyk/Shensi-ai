# 智能体中心单一前端壳设计

**状态：** 已确认，待实施

**日期：** 2026-08-23

## 1. 背景

当前前端同时保留了两套入口体验：

- 旧白色 CRM 工作台及其默认 `#dashboard` 入口；
- 黑色智能体业务壳，其中 `#agents` 展示“智能体中心”和六张业务智能体卡牌。

双入口导致用户容易打开错误页面，也让后续开发难以判断哪套导航、样式和启动逻辑是产品权威入口。已经确认黑色 `#agents` 页面才是后续唯一前端方向。

## 2. 目标

1. 将黑色智能体业务壳升级为产品唯一前端壳。
2. 登录后以及直接打开项目时，默认进入“智能体中心”。
3. 保留获客、私域、工作流、财务智能体等现有业务能力。
4. 删除旧白色 CRM 工作台、旧导航和确认无依赖的旧启动代码。
5. 不改变后端、数据库、API 合同、权限边界或现有业务数据。

## 3. 方案选择

评估过三种方案：

1. 只隐藏旧路由：改动最少，但旧壳和重复依赖继续存在，后续仍会产生歧义。
2. 提取黑色壳为唯一应用壳，再删除旧白色壳：迁移风险可控，并能彻底统一入口。
3. 重写全新前端：可以获得最干净的结构，但会重复实现已经存在且已验证的业务页面。

采用方案 2。

迁移方式参考 Strangler Fig 思路：先让新壳成为唯一入口并承接现有功能，验证完成后再删除旧路径，避免一次性删除造成不可见依赖断裂。参考实现思路：[Strangler Fig Introduction](https://github.com/stevekinney/stevekinney.net/blob/main/courses/enterprise-ui/strangler-fig-introduction.md)。

## 4. 权威界面

唯一权威首页为当前 `#agents` 页面，核心特征包括：

- 黑色侧边栏和顶部导航；
- 标题“智能体中心”；
- 副标题“配置自动营销智能体与执行状态”；
- 六张业务智能体卡牌：
  - AI 经营总管；
  - 财务分析；
  - 利润分析；
  - 成本分析；
  - 现金流分析；
  - 税务健康。

现有 `frontend/src/replica-dashboard.ts`、`frontend/src/replica-dashboard.css`、`frontend/src/growth/agents/` 以及它们实际依赖的业务模块是迁移审计的起点。不能按目录名称简单删除 `demo`、`legacy` 或旧入口文件，因为正确的黑色界面目前仍可能由这些启动链路装配。

## 5. 路由与启动行为

- `/`、空 Hash 和 `#dashboard` 统一规范化到 `#agents`。
- 登录成功后默认进入 `#agents`。
- 不再渲染旧白色 CRM 工作台。
- 黑色壳内仍保留获客、私域、工作流、财务分析及其他已存在的有效业务路由。
- 已删除或不再支持的旧 Hash 统一回到 `#agents`，不展示空白页或旧壳。
- 刷新任一受支持业务路由时，仍由同一黑色应用壳恢复页面。

## 6. 保留边界

必须保留：

- 黑色应用壳、侧边栏、顶部导航和响应式样式；
- `#agents` 智能体中心及六张业务卡牌；
- 获客、私域、工作流、财务委员会和智能体详情等现有业务模块；
- 登录、会话、CSRF、RBAC 和 workspace 权威解析；
- 前端 API 客户端、生成合同类型和错误处理；
- 后端服务、数据库结构、worker、API 合同及现有数据。

## 7. 删除边界

验证新入口稳定后删除：

- 旧白色 CRM 首页 DOM 和专属启动逻辑；
- 旧白色导航及其默认 `#dashboard` 页面实现；
- 只服务于旧壳且没有其他消费者的组件、样式和资源；
- 重复的路由分发、重复的应用初始化和不可达页面代码；
- 已失效且会误导开发者的旧前端说明。

删除前必须用静态依赖搜索、类型检查和浏览器验收确认没有被黑色壳或业务页面复用。删除操作由 Git 提交保护，可通过 revert 恢复，不删除后端或数据库数据。

## 8. 实施顺序

1. 为根路径、登录后入口和 `#dashboard` 兼容跳转补充失败测试。
2. 把黑色壳的启动、路由和页面挂载整理为唯一前端入口。
3. 将根路径和登录成功行为切换到 `#agents`。
4. 验证全部保留业务页面仍在黑色壳内可达。
5. 建立旧壳依赖清单，删除确认不可达的白色 CRM 代码。
6. 清理重复样式、资源、路由和初始化代码。
7. 更新 README、开发入口和当前状态文档。
8. 完成类型、单元、自测试、构建和浏览器验收后提交。

## 9. 错误与兼容行为

- 未登录访问受保护页面时继续进入现有登录流程；认证成功后回到 `#agents` 或安全的原目标路由。
- 权限不足仍使用现有服务端权威结果，前端不能伪造 workspace 或 capability。
- 未知 Hash 安全回退到 `#agents`。
- API 失败、会话过期和权限失败继续使用黑色壳内统一反馈，不重新显示旧 CRM。
- `#dashboard` 只作为短期兼容入口，不再拥有独立页面实现。

## 10. 验收标准

### 10.1 页面验收

- 打开 `/` 直接进入黑色“智能体中心”。
- 打开 `#dashboard` 自动进入 `#agents`。
- 登录成功默认展示六张智能体卡牌。
- DOM、样式和网络启动链路中不再出现旧白色 CRM 工作台。
- 六张智能体卡牌及保留导航入口可以正常打开对应业务页面。
- 1440、1366、1024 和移动端关键宽度下无横向溢出或导航不可用。

### 10.2 功能验收

- 登录、退出、会话恢复和权限控制正常。
- 获客、私域、工作流和财务相关关键路径仍可进入。
- 前端不改变后端请求的 workspace、capability、CSRF 和幂等边界。
- 删除旧代码后不存在失效导入、重复初始化或不可恢复的深链路刷新。

### 10.3 工程门禁

- 前端类型检查通过；
- 前端单元测试和自测试通过；
- Vite 生产构建通过；
- 关键 Playwright 浏览器路径通过；
- `git diff --check` 通过；
- README、前端 README 和当前状态文档与唯一入口一致。

## 11. 数据与安全边界

本次改造只调整前端壳、路由和旧代码清理：

- 不删除、迁移或重建数据库；
- 不修改后端领域规则；
- 不放宽身份认证、权限、CSRF 或 workspace 隔离；
- 不引入真实客户数据、凭据或新的外部服务；
- 不把前端展示状态当成服务端业务权威。

## 12. 回滚

- 新壳入口切换和旧壳删除应分成可独立回滚的提交。
- 若入口切换出现问题，可先回退路由提交恢复旧入口。
- 若删除后发现隐藏依赖，可只回退清理提交，不回滚后端或业务数据。

## 13. 非目标

- 不重做六张智能体卡牌的视觉设计；
- 不新增后台管理系统；
- 不重构后端或数据库；
- 不在本次工作中增加新的智能体业务能力；
- 不把 `#financial-council` 或裸 `#growth/agents` 页面设为产品首页。
