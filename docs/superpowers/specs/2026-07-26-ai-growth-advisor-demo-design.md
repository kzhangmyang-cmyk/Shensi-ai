# AI 增长参谋与全网获客指挥中心演示强化设计

日期：2026-07-26

状态：已通过产品方向、首屏结构、演示脚本和页面范围评审

目标版本：GoodJob 1.09 二次开发版本

## 1. 背景

当前系统已经具备完整的 AI 获客后端能力，包括：

- 六个真实搜索 Provider；
- 客户 BYOK 搜索连接；
- 九个官方大模型 Provider；
- Pi 获客智能体及受控业务工具；
- 获客计划、审批、运行、暂停、恢复和取消；
- 候选客户、证据、身份确认、意向评分和财务价值；
- 客户作战卡、人工审核、CRM 转换和结果反馈；
- AI 增长参谋会话与任务接口。

但是，当前前端没有把这些能力组织成一个老板能够快速理解的演示故事。现有工作台以传统 CRM 信息架构为主，AI 建议被埋在普通卡片和表格中；“自动获客”页仍出现“功能持续优化中”的弱化文案；AI 配置页在窄屏下存在明显布局破坏，并且页面中的厂商描述与当前官方 Provider 契约不完全一致。

## 2. 产品目标

本次设计面向潜在客户中的老板、管理者和采购决策人。

客户应在前三分钟形成一个明确认知：

> 这个 AI 能够根据我的业务目标，从多个公开搜索来源主动发现潜在客户，并且告诉我发现了谁、为什么值得跟进。

本次设计优先强化“发现商机”的可见性。客户作战卡、财务价值和销售线索交接作为结果证明，不在首屏争夺主叙事。

### 2.1 成功标准

1. 登录后第一屏就是 AI 增长参谋，而不是传统 CRM 数据看板。
2. 用户可通过自然语言或行业模板发起一次完整获客任务。
3. 用户能看到 AI 生成搜索计划、等待确认并按计划执行。
4. 用户能看见真实启用的数据源、执行步骤、候选客户和证据。
5. 用户能在不离开指挥中心的情况下打开客户作战卡。
6. 演示模式能稳定完成一条 90 秒以内的确定性演示路径。
7. 真实模式严格调用客户已配置的官方搜索连接，不伪造 Provider 状态。
8. 1440、1366 和 1024 像素宽度下都不存在横向溢出或内容被压成窄条的问题。
9. 真实模式中的候选客户、运行统计和财务价值都能关联到本次运行，不能按时间或全局列表猜测。

## 3. 非目标

本次不包含：

- 重做整个 CRM；
- 对已发布的 AI 获客 V1 契约做破坏性修改；第 8.1 节定义的向后兼容展示投影除外；
- 新增搜索 Provider 或模型 Provider；
- 自动加好友、自动私信、自动评论或自动群发；
- 3D 数字人、语音克隆或纯装饰性的“科幻驾驶舱”；
- 原生移动端；
- 完整重做财务经营决策模块；
- 未标注的模拟数据或伪造实时搜索状态。

## 4. 方案选择

评审过三种方案：

1. **AI 全网获客指挥中心**：以任务、实时执行和机会发现为核心。
2. **贾维斯式对话首页**：以聊天框为核心，容易被误解为套壳聊天机器人。
3. **老板经营驾驶舱**：商业结果清晰，但不能突出 AI 主动找客户的过程。

最终选择方案 1，并在任务完成后吸收方案 3 的老板摘要能力。

## 5. 信息架构

主导航调整为：

1. AI 增长参谋
2. 全网商机
3. 线索池
4. 客户作战
5. CRM 跟进
6. 经营分析
7. 设置

本次只修改与演示主线直接相关的页面，不扩展无关路由。

## 6. 核心页面与组件

### 6.1 AI 增长参谋首页

首屏标题：

> AI 正在为你发现全网商机

首屏包含：

- 自然语言任务输入框；
- 行业模板切换；
- 演示模式与真实搜索模式切换；
- 已连接搜索来源健康状态；
- 最近任务和继续任务入口。

行业模板至少包括：

- 企业服务；
- 外贸制造；
- 装修；
- 美业；
- 教培；
- 自定义行业。

默认模板为“企业服务”，但产品逻辑保持行业无关。模板只负责填充目标行业、地区、企业规模、需求信号和排除条件，用户可以修改。

### 6.2 搜索计划确认面板

自然语言目标不能直接触发外部搜索。AI 先生成结构化计划，面板展示：

- 目标地区；
- 目标行业；
- 企业规模；
- 重点需求信号；
- 排除对象；
- 搜索主题和关键词；
- 将使用的数据源；
- 预计搜索范围，即计划预算中的最大请求数、最大结果数、费用上限和执行时长，不承诺实际获客数量；
- 预算或配额提示。

用户可修改计划、确认计划或取消任务。确认动作映射现有计划审批接口，不能由前端绕过。

### 6.3 AI 实时执行台

桌面端采用双栏布局：

- 左侧为任务执行过程和搜索查询流；
- 右侧为实时出现的候选商机。

执行步骤包括：

1. 理解目标客户画像；
2. 生成搜索主题与关键词；
3. 调用已启用搜索连接；
4. 读取并整理公开网页；
5. 识别企业主体；
6. 合并重复企业；
7. 提取需求证据；
8. 评估意向与价值。

顶部成果指标包括：

- 已检索公开来源；
- 已分析网页；
- 已发现企业；
- 去重后候选客户；
- 高意向商机；
- 预计收入和待评估数量。

候选商机卡包含：

- 企业名称；
- 行业与地区；
- 需求信号摘要；
- 来源数量；
- 证据置信度；
- 意向等级；
- 已有财务价值；没有可信财务决定时显示“待评估”，不生成虚假金额；
- 查看客户作战卡入口。

### 6.4 客户作战卡抽屉

用户在执行台点击候选客户后，以右侧抽屉打开作战卡，不打断当前任务上下文。

内容包括：

- 客户基本信息；
- 需求判断及来源证据；
- 身份确认状态；
- 意向评分和财务价值；
- 可能的现有供应商；
- 推荐部门和决策角色；
- 推荐连接方式；
- 老板、运营、采购等不同角色的开场草稿；
- 不建议动作；
- 创建人工审核任务入口。

未经确认的身份、供应商或采购偏好必须显示为“推测”并附置信度，不能以事实语气呈现。

真实模式下，如果候选尚无有效作战卡，“生成作战卡”按钮必须向 AI 增长参谋发送受控任务，由 Pi 的 `build_battle_card` 工具执行；任务成功后再读取作战卡。普通前端不能直接调用受 `requireDirectDomainWrites` 保护的领域写接口。

### 6.5 老板结果摘要

任务完成后，AI 用一句可朗读的摘要汇报：

> 本次从 6 个公开数据源发现 86 家企业，确认 17 条有效商机，其中 5 条建议优先跟进；3 条已完成财务评估，预计收入 51.2 万元，另有 2 条待评估。

摘要下提供三个主动作：

- 查看优先客户；
- 为首位优先客户生成作战卡；
- 将已审核客户转换到线索池并为当前负责人创建跟进任务。

真实模式执行第三个动作时，先调用候选转换接口，再使用现有 CRM 待办接口为当前负责人创建跟进任务；任一步失败都必须显示真实状态并允许重试。演示模式只展示同结构的动作预览和预期结果，不调用转换或待办接口。

真实模式中的金额仅使用最新、已持久化的财务价值决定。若本次运行的高意向客户尚未全部完成财务评估，摘要必须同时显示“已评估数量/高意向数量”，不能用默认客单价补齐。演示模式数字必须明确标注为演示数据。

## 7. 页面状态模型

指挥中心必须覆盖以下显式状态：

| 状态 | 页面行为 |
|---|---|
| `idle` | 展示任务输入、行业模板和连接状态 |
| `planning` | 展示 AI 正在生成结构化搜索计划 |
| `awaiting_approval` | 展示计划确认面板 |
| `running` | 展示实时执行台、候选商机和成果指标 |
| `paused` | 保留已有结果并提供恢复或取消 |
| `partial_success` | 任务继续，明确标记失败来源和成功来源 |
| `completed` | 展示老板摘要和后续动作 |
| `cancelled` | 保留已产生证据，明确任务已取消 |
| `connection_required` | 引导配置搜索连接，不制造运行假象 |
| `empty` | 解释没有结果并建议放宽条件 |
| `failed` | 提供可理解的原因、重试或返回计划修改 |

状态转换由后端计划、任务、运行和分片状态驱动，前端不能仅通过计时器伪造真实模式进度。

### 8.1 必要的向后兼容展示契约

现有 V1 能执行获客计划，但不能完整支撑本设计的三个可信展示要求。实施前先增加以下向后兼容契约，不修改既有字段的含义：

#### A. 结构化计划草稿

`POST /api/v1/acquisition/copilot/sessions/:id/messages` 增加可选字段：

```json
{
  "message": "用户的自然语言获客目标",
  "responseMode": "plan_draft"
}
```

默认 `responseMode` 仍为现有的 `assistant`，因此旧客户端行为不变。`plan_draft` 模式：

- 不调用搜索工具；
- 使用当前会话绑定的模型快照；
- 通过服务端 Schema 校验输出；
- `CopilotTask.result` 增加可选 `planDraft`；
- 模型只生成 `name`、`objective`、ICP、主体渠道、查询意图、预算意图和停止条件，不能生成连接 ID、凭据版本、模型快照、`operationId` 或已分配预算；
- 服务端根据当前用户可见且已启用的搜索连接，补全并校验 `providerConnections`、搜索操作、连接版本、`operationId`、分片预算和当前会话允许使用的 `modelConnectionId`；
- `planDraft` 是服务端组装的最终计划草稿，与公开创建计划请求兼容，但不包含只能由创建计划服务绑定的模型快照；
- 编辑 ICP、查询或预算意图后必须重新生成服务端草稿，前端不能就地修改连接和操作快照；
- 正式创建计划时仍由现有计划服务重新校验租户、连接状态、凭据版本和预算；
- 校验失败时任务失败并返回稳定错误码，前端不能解析自由文本冒充计划。

#### B. 运行展示投影

新增只读接口：

```text
GET /api/v1/acquisition/runs/:id/presentation?after=...&limit=...
```

返回：

- 运行状态和更新时间；
- 搜索分片及 Provider 状态；
- 原始结果、接受结果、重复结果和失败结果计数；
- 当前时刻的完整摘要快照；
- 从 `after` 之后新增或更新的候选投影事件；
- 每个候选事件中的最新资格决定、最新财务价值、来源平台和证据数量；
- 不透明且签名的 `nextAfter` 事件游标；
- `hasMore`，表示当前水位之前是否还有未读取事件。

关联必须由服务端根据运行、原始命中、主体覆盖事件和候选主体引用计算，不能由前端使用创建时间猜测。

`after` 是增量事件游标，不是冻结结果集的分页快照。它必须绑定租户、操作者、`runId` 和最后一个已读取的 `(createdAt, eventId)`，并经过 HMAC 签名。客户端处理规则：

1. 首次请求不传 `after`，从运行起点读取；
2. 按 `candidateId` 合并候选新增或更新事件；
3. `hasMore=true` 时立即携带 `nextAfter` 继续读取；
4. 追平当前水位后保留 `nextAfter`，运行中按固定间隔继续轮询；
5. 摘要和 Provider 状态始终以最新响应中的完整快照覆盖；
6. 运行结束且 `hasMore=false` 后停止轮询。

#### C. 最新财务价值读取

新增只读接口：

```text
GET /api/v1/acquisition/candidates/:id/financial-value
```

返回候选当前资格决定绑定的最新财务价值；没有记录时返回稳定的 `404 resource_not_found`。该接口不触发估算，不生成默认金额。

### 8.2 老板摘要指标口径

| 指标 | 计算口径 |
|---|---|
| 已检索公开来源 | 本次运行实际执行过至少一个分片的不同 Provider 数 |
| 已分析网页 | 本次运行持久化的执行页数量 |
| 已发现企业 | 本次运行关联的不同组织主体数 |
| 去重后候选客户 | 本次运行关联的不同候选客户数 |
| 有效商机 | 最新资格等级为 S、A 或 B，且硬门禁通过、未进入勿扰的候选数 |
| 高意向商机 | 最新资格等级为 S 或 A 的候选数 |
| 预计收入 | 对已完成财务评估的高意向客户，按币种分别汇总最新 `expectedRevenueMinor` |

不同币种不得相加。界面默认优先显示 CNY；存在多币种时以分组形式展示。没有财务价值的客户只计入“待评估”，不进入金额汇总。

## 9. 搜索来源和模型设置

真实搜索来源只显示当前后端支持并且用户已连接的 Provider：

- 百度 AI 搜索；
- 腾讯联网搜索；
- Tavily；
- Serper；
- Brave Search；
- SerpApi。

设置页需要同步当前官方模型 Provider 契约，不再用“任意 Base URL + 自定义兼容服务”作为主要交互。设置页面应优先展示官方厂商、已认证模型、连接状态、凭据版本和测试结果。

本次需要修复设置页的响应式布局，因为它是演示中的阻断问题；但不在本次重做全部设置功能。

## 10. 演示模式

演示模式与真实模式共享同一套页面组件和 ViewModel，不复制一套独立页面。

演示模式要求：

- 明确显示“演示数据”标签；
- 使用固定、真实结构的行业样例；
- 在 45 至 90 秒内可配置地回放完整流程；
- 支持暂停、继续和“跳到结果”；
- 每一步都使用真实系统存在的业务动作名称；
- 不调用外部搜索 API；
- 不写入正式 CRM 或正式审核记录；
- 切换到真实模式时清空演示运行上下文。

演示模式的目标是稳定呈现产品流程，不冒充真实搜索。

## 11. 视觉与动效规范

### 11.1 视觉方向

- 延续现有深蓝企业级设计语言和已有设计 Token；
- 压缩当前顶部工具栏，使首屏主要空间归属任务与结果；
- 使用现有图标体系或一致的图标库，不使用 emoji 充当产品图标；
- 通过来源状态、执行时间线、证据、数字变化和候选卡片体现 AI；
- 不增加无业务意义的粒子、雷达扫描、3D 球体或数字人；
- 产品名称使用租户或系统配置，不添加宣传图式水印。

### 11.2 动效

允许的动效：

- 任务步骤状态切换；
- 进度条；
- 候选客户进入列表；
- 成果数字递增；
- 作战卡抽屉进出；
- 部分失败来源的状态变化。

必须支持 `prefers-reduced-motion`。真实模式的动画只能反映后端状态，不能让已失败或未运行的步骤看起来正在执行。

### 11.3 响应式

- 1440 和 1366：完整双栏执行台；
- 1024：执行过程与候选列表调整为主从布局，但不隐藏核心状态；
- 小于 1024：本次只保证可用，不以移动端演示为目标；
- 所有表单、选择器和配置卡必须设置合理最小宽度和换行规则；
- 页面不得出现横向滚动；
- 修复当前 AI 配置页窄屏压缩问题。

## 12. 错误与恢复

### 12.1 未配置搜索连接

收到 `SEARCH_PROVIDER_CONNECTION_REQUIRED` 时：

- 停留在 `connection_required` 状态；
- 解释需要客户自己的官方 API Key；
- 提供“配置搜索来源”和“使用演示模式”两个动作；
- 不显示虚假的搜索进度。

### 12.2 部分 Provider 失败

- 任务进入 `partial_success`；
- 成功来源继续执行；
- 失败来源显示错误类别、重试时间或配额提示；
- 结果摘要说明本次覆盖范围受到影响。

### 12.3 计划并发冲突

ETag 或 `If-Match` 冲突时：

- 提示计划已被其他成员更新；
- 重新读取最新版本；
- 用户重新确认后才能批准；
- 不静默覆盖。

### 12.4 无结果

- 展示已搜索来源和已执行查询；
- 给出放宽地区、规模、行业或需求信号的具体建议；
- 可一键回到计划修改；
- 不把“零结果”包装成成功。

### 12.5 模型或任务失败

- 保留已经产生的可信证据；
- 清楚区分模型生成失败、搜索失败和网络失败；
- 提供重试、修改计划或结束任务；
- 不自动切换到未经用户授权的模型或凭据。

## 13. 三分钟演示路径

### 0:00–0:20

选择“企业服务”模板，输入：

> 帮我寻找上海近期可能有数字化采购需求、员工规模 50 人以上的制造企业。

### 0:20–0:40

展示 AI 生成的客户画像、需求信号、搜索主题、排除条件和数据源。用户点击“确认并开始”。

### 0:40–1:30

展示搜索 Provider、执行步骤、查询流、候选客户和成果数字实时变化。

### 1:30–2:25

打开排名第一的候选客户作战卡，查看需求证据、决策角色和开场策略。

### 2:25–3:00

展示老板结果摘要和“转为线索并创建跟进任务”的动作预览，并明确说明：真实模式确认后会写入线索池和当前负责人的今日待办，演示模式不写正式数据。

演示结束话术：

> 普通获客软件只是给您更多名单；我们的 AI 会主动找商机、验证需求，并直接告诉销售下一步怎么做。

## 14. 测试与验收

### 14.1 交互测试

- 行业模板正确填充任务参数；
- 自然语言任务能够生成可修改计划；
- 未审批计划不能创建运行；
- 暂停、恢复和取消动作正确映射后端；
- 候选客户增量进入结果列表；
- 作战卡抽屉不破坏运行上下文；
- 缺少作战卡时必须通过 AI 增长参谋受控调用 `build_battle_card`，普通前端不得直接调用受保护的领域写接口；
- 完成后能够生成老板摘要和后续任务。

### 14.2 状态测试

为第 7 节的每一种页面状态提供独立 Fixture 和测试。演示模式与真实模式使用相同组件状态契约。

### 14.3 契约测试

- 前端 ViewModel 适配层使用 V1 OpenAPI 契约；
- 不允许页面组件自行构造可信快照字段；
- 错误码映射必须覆盖连接缺失、并发冲突、配额、部分失败和取消；
- `plan_draft` 响应必须通过服务端 Schema 校验，不能回退为前端解析模型自由文本；
- `plan_draft` 中的连接、操作、版本和预算分配必须由服务端补全；伪造连接 ID、跨租户连接或过期凭据版本必须被拒绝；
- 运行展示投影必须只返回与目标 `runId` 有服务端来源链关联的候选；
- 运行展示游标必须绑定租户、操作者和 `runId`；篡改游标、跨运行复用游标必须被拒绝；
- 重放同一 `after` 必须得到可幂等合并的候选事件；追平水位后新产生的事件必须能被下一次轮询读取；
- 财务价值读取必须与候选当前资格决定版本一致；
- 受保护的作战卡领域写接口仍需拒绝普通前端；受控 Pi 工具成功后才能读取新作战卡；
- 演示模式必须通过网络断言确认未调用搜索、候选转换、审核写入或 CRM 待办接口；
- 三个向后兼容展示契约必须加入生产 OpenAPI 和契约测试；
- 既有 V1 契约测试必须继续通过。

### 14.4 视觉回归

在以下视口截图并对比：

- 1440 × 900；
- 1366 × 768；
- 1024 × 768。

至少覆盖：

- 初始首屏；
- 计划待确认；
- 运行中；
- 作战卡打开；
- 任务完成；
- AI/搜索来源设置页。

使用相同视口把改造前截图和改造后截图并排检查，重点确认布局、间距、字体、边框、抽屉、溢出和响应式行为。

### 14.5 可访问性

- 所有主动作可通过键盘完成；
- 焦点状态清晰；
- 动态状态通过文本同步表达；
- 颜色不是唯一状态信号；
- 文字和背景满足企业后台可读性要求；
- 尊重减少动态效果设置。

## 15. 实施边界

本设计由一个实施计划承接，但必须按四个可独立验收的阶段推进：

1. 向后兼容展示契约与前端 ViewModel；
2. 稳定演示模式与三分钟演示链路；
3. 真实搜索运行、运行候选关联和财务价值接入；
4. 响应式、设置页阻断修复、可访问性和视觉回归。

不得跳过第一阶段直接在前端按时间、名称或全局列表猜测运行结果。

前端实施应优先创建小而明确的组件和适配层，不继续把所有新逻辑直接堆入现有大型 `frontend/index.html`。

推荐边界：

```text
AI 增长参谋页面
├── 任务输入与行业模板
├── 计划确认
├── 运行状态适配器
├── 实时执行台
├── 候选商机列表
├── 客户作战卡抽屉
├── 老板结果摘要
└── 演示模式数据适配器
```

各组件只依赖稳定 ViewModel，不直接依赖后端持久化结构。该边界允许前端设计和后端契约由不同协作者并行维护。

## 16. 最终验收口径

该设计完成的标志是：

1. 老板打开系统后无需讲解就能看懂“AI 可以帮我找客户”。
2. 三分钟内能完成任务创建、计划确认、执行观察、查看作战卡和后续动作预览；真实模式可以把已审核客户转入销售线索池并创建当前负责人待办。
3. 演示模式稳定且明确标注；真实模式严格反映实际 Provider。
4. 每个商机有来源和证据，不能只显示 AI 结论。
5. 页面在三个目标桌面宽度下均可用。
6. 当前 AI 配置页的响应式阻断问题被修复。
7. 除第 8.1 节的向后兼容展示契约外，不修改既有 V1 语义。
8. 不引入自动触达或未经授权的数据处理。
