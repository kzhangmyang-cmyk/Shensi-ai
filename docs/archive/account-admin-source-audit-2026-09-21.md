## 已确认目标与决策边界

- 后台供神思运营者管理全部客户企业、账号、停用/恢复和使用权限。
- 套餐固定为试用版、基础版、专业版；按企业工作区授权，员工继承企业套餐并受自身角色限制。
- 先境外部署，后迁阿里云；复用当前仓库、Express、MySQL、契约生成与桌面执行链。
- 套餐名称已确认；模块划分、试用天数、席位/用量、价格尚未确认。上一轮“基础版不含获客”只是建议，不作为实施依据。
- 本轮仅检查与规划，不购置资源、不发布、不操作真实客户账号、不迁移数据库。

## 精简后台方案

独立浏览器运营入口，仍在同一仓库与后端中实现。导航只保留四页，首页不另建大屏。

| 页面 | 第一版内容 |
| --- | --- |
| 企业客户 | 企业名/工作区ID、联系人、状态、套餐、到期日、成员数；搜索筛选；详情内开通、冻结、恢复、续期 |
| 账号 | 所属企业、登录名、企业角色、账号状态；创建、停用/恢复、发起一次性密码重置、撤销会话；不展示密码或平台密钥 |
| 套餐授权 | 三种套餐的模块权益与版本；企业选择套餐及期限；变更前展示影响，禁止前端自行授予权益 |
| 操作日志 | 操作者、目标企业/账号、动作、脱敏前后值、原因、结果、时间及请求ID；筛选与受控导出 |

第一版人工开通、人工续期；不做支付、发票、优惠券、代理商、复杂组织树、自定义权限设计器、代登录和批量硬删除。日志不能由普通运营账号修改或删除。

### 身份与授权

平台所有者与运营员两种固定平台角色；客户继续使用企业 admin/manager/sales。平台成员关系单独存储，不能由客户角色推导；现有 super_admin 账号需逐一确认用途后迁移授权，禁止自动批量晋升。

业务许可 = 用户有效 ∩ 企业有效 ∩ 套餐权益 ∩ 企业内角色能力 ∩ 对象归属 ∩ 既有人工审批/执行准入。

套餐不扩大客户业务数据可见范围，不替代外联人工确认。冻结企业会阻止业务访问，运营恢复后才能继续；套餐到期建议允许读取/导出既有资料，禁止新模型调用、新采集及外联。用户停用则拒绝登录/访问。套餐到期与企业冻结是不同状态。

停用/降级必须覆盖已排队任务、worker、桌面领取及迟到请求。已执行结果继续保存；失败与撤销不自动退还外部已发生费用。授权服务失败时拒绝新增执行，不默认放行。

### 套餐规则

稳定标识 `trial/basic/pro`，可版本化模块集合、席位上限、有效期规则。先做三种套餐的固定编辑表单；没有确认的模块/额度不得自动赋予无限量。套餐更改产生新版本，既有企业保留原版本，主动升级/降级必须有操作记录。

首发建议邀请/人工开通，公开注册产生待开通企业；这是待评审建议，当前公开注册行为不在本轮修改。后续开放自动试用时，再定义试用时长、重复试用限制、成本额度和原子预占/结算。对已有账号使用显式迁移映射，不自动当作专业版，也不能一上线就批量停用。

### 最小数据与接口边界（提议，未实现）

- `workspaces`：沿用当前 teamId/workspaceId 值补企业元数据及状态，不重新生成业务归属ID。
- `platform_memberships`：userId、owner/operator、状态；与客户角色隔离。
- `plan_versions`：三类套餐及版本、模块权益、席位上限。
- `workspace_subscriptions`：workspaceId、套餐版本、生效/到期时间、状态、revision；一企业一个当前授权。
- `platform_audit_events`：追加式脱敏事件。管理写入与成功审计同事务，失败尝试另记安全日志。
- `account_recovery_tokens` / `platform_sessions`：仅保存一次性令牌摘要、失效时间和必要会话撤销信息；复用 users 与 scrypt，不复制业务用户表。

拟新增 `/api/platform/v1/` 的企业、账号、授权、审计资源，以及客户只读 `/api/me/entitlements`；管理命令有幂等键与revision冲突检查。具体 OpenAPI 后续设计后生成类型，不手写前端 DTO。旧 `/api/accounts` 路由必须同时收口并调用同一身份服务，防止绕过新规则。

新增领域表使用独立事务 repository，不纳入全库快照替换。复用用户身份时必须同步改造相关旧读写路径，或在单实例事务适配层维持内存与DB一致；不能让新后台直接改DB而旧 persist 覆盖它。多副本支持属于后续独立里程碑。

## 境外部署到阿里云

### 境外首发

建议选择靠近首批用户、且实测国内访问可用的境外区域，使用常驻容器计算和同区域持久MySQL。保留固定自有API域名；运营前端独立入口，其API通过同源网关转发，避免扩大跨域Cookie范围。桌面浏览器/Profile留在客户Mac，云端承载业务API、账号授权、任务状态及运营页面。

可选常驻托管容器（运维少）或境外VM上的Docker（迁移直观、需自行运维）。先复用现有镜像和配置，云厂商只放在部署适配层；现有生产Compose强依赖远程Sidecar，桌面云模式需新增专用部署配置，不能原样全栈照搬。第一阶段若保留当前单实例持久化，采用可告知的停机发布与备份恢复，不承诺无停机和高可用。

Render免费服务会休眠且不能提供持久磁盘，继续仅作联调；不能把付费升档当成解决单实例锁或应用一致性的方案。[官方限制](https://render.com/docs/free)

上线部署配置需明确：HTTPS终止/证书续期、受信代理与限流、CORS、Secure Cookie、生产种子关闭、运营MFA、密钥注入、DB TLS/最小权限、日志脱敏、备份异地保存、worker开关和已验证桌面准入。不得沿用migration_locked状态宣称桌面写入已开放。

### 阿里云目标

同一镜像先落ECS/容器运行环境，数据库选择通过兼容验证的RDS MySQL，静态资源/对象备份可迁OSS。身份ID、套餐ID、加密AAD和API契约不随厂商改变。不得假定源MySQL 8.4可无损降级到8.0；建库前核对版本、排序规则、JSON/DDL和迁移工具支持范围。

密钥从独立受控清单恢复，保留密文解密所需原密钥及版本；不要在创建新云环境时重新生成密钥后直接指向旧密文。JWT可选择切换时统一重新登录。对象文件若存在，需要同时迁移内容、元数据与校验摘要；桌面本机Profile不是云迁移对象。

阿里云区域（境内或境外）、备案和数据处理要求在选择地域后单独核实；本方案不假定迁到阿里云就等于迁入中国内地，也不替代上线地域合规评估。

### 小规模迁移首选维护窗口

1. 用同版本镜像和新空库演练，建立真实schema/表/行/附件清单；验证账号、授权、报告解密和审计完整性。
2. 冻结新写入、定时器、worker和桌面执行领取；让在途动作完成或进入可对账状态，不对不明回执重试。
3. 备份并恢复到新目标，比较计数/摘要/约束与业务样本；原库不覆盖、不删除，工具适配必须先验证受管库权限。
4. 保持两端执行关闭，切固定域名入口、验证TLS/Cookie/登录/企业隔离/到期拒绝和桌面重连；仅启用目标端写入及执行者。
5. 目标尚无新写入可切回原只读快照后恢复；目标已有写入须先停写并核对迁回增量，不能只回滚DNS导致数据丢失。

数据规模或停机要求上升后再评估DTS全量+增量，先核对版本、binlog、权限、网络和源托管商支持。DTS不迁移应用密钥、任务执行权和本机Profile。[阿里云MySQL迁移文档](https://www.alibabacloud.com/help/en/dts/user-guide/migrate-data-from-a-self-managed-mysql-database-connected-over-express-connect-vpn-gateway-or-smart-access-gateway-to-an-apsaradb-rds-for-mysql-instance)

## 分阶段交付与验收

1. 身份与授权底座：确认套餐规则；OpenAPI与数据设计；事务身份服务、平台角色、MFA/恢复、企业状态及套餐校验。以跨租户拒绝、公开注册不提权、并发/失败回滚、停用即时失效为验收。
2. 四页运营后台：开通企业→创建账号→选套餐→登录使用→停用拒绝→恢复→到期限制→续期，整链都有真实MySQL与审计记录；后台列表分页，不一次返回全部账号。
3. 境外小规模上线：备份恢复演练、单实例发布/回退、云端HTTPS和桌面准入、真实设备验收；人工开通首批客户。收费模块逐项验收，未交付功能不纳入宣传套餐。
4. 阿里云迁移演练与正式窗口；高可用、多副本、自动付费、SSO按真实需求另立阶段。

通用检查执行 `./scripts/context-check`、`pnpm test`、`pnpm build`、`git diff --check`；桌面另跑 `pnpm typecheck:desktop`。它们不替代目标环境部署、恢复、实际设备与外部平台验收。本轮运行结果记录在进度账本。

下一轮需决策：三套餐模块/席位/试用天数与平台承担的模型额度；公开注册还是邀请开通；境外区域与预算；可接受发布停机时长。这些不影响本轮缺口结论，但会决定实施计划。
