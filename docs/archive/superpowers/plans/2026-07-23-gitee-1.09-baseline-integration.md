# Gitee 1.09 Baseline Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Safely promote Gitee GoodJob 1.09 (`5732e20`) to the shared AI-growth development baseline without losing local product documents or committing generated artifacts.

**Architecture:** Preserve local deliverables in one documentation-only commit, create a clean integration branch directly from Gitee 1.09, and cherry-pick only that documentation commit. Keep Gitee as the read-only upstream baseline and use the private GitHub repository for collaborative review and subsequent Codex feature branches.

**Tech Stack:** Git, GitHub CLI, Node.js, npm workspaces, TypeScript, Vite, Express, MySQL-compatible backend tests.

## Global Constraints

- Do not run `git reset --hard`, `git checkout -- .`, `git clean`, or destructive file removal.
- Do not directly modify or push Gitee `origin/master`.
- Do not commit `node_modules`, `dist`, `.DS_Store`, or `*.tsbuildinfo`.
- Preserve all three `docs/product/*.docx` files byte-for-byte.
- The target code baseline must be exactly Gitee commit `5732e20` before local documentation commits are applied.
- Use GitHub Pull Requests for the final baseline review.
- Do not add Pi or change application behavior during this baseline integration.
