# 抖音 AI 获客首发版：GitHub Issue 拆解草案

日期：2026-08-05

状态：待确认后发布

拆解方式：可验收的纵向 tracer-bullet，每个 Issue 同时覆盖所需契约、后端、前端和测试，不按“先写完全部后端、再写全部前端”拆分。

## 1. 协作约定

### 角色

- **项目负责人（你）**：统一负责产品边界、优先级、平台账号、验收和发布决定。
- **Codex**：按 Issue 在独立分支完成契约、后端、前端、Skill、测试和文档，并提交可审查的 PR。
- **外部依赖**：抖音应用申请、真实账号授权、密钥和生产发布仍由你确认，Codex 不代替账号所有者授权。

### 分支

- `feature/douyin-contract-source`
- `feature/douyin-acquisition-overview`
- `feature/douyin-plan-flow`
- `feature/douyin-public-discovery`
- `feature/douyin-connector`
- `feature/douyin-signal-scoring`
- `feature/douyin-action-policy`
- `feature/douyin-conversation-outcome`

每个 Issue 一个短生命周期分支和 PR；不得直接提交 `main`。先合并共享契约，再由 Codex 按依赖串行推进；只有互不修改同一契约的任务才并行。

### Issue 类型

- **AFK**：契约和验收明确，可让 Codex 独立实现并提交 PR。
- **HITL**：涉及产品权限、真实账号、平台申请、密钥、法律/运营文案或上线动作，需要负责人参与。

### #00 [HITL] 冻结抖音能力清单与自动化政策

**目标用户故事**：#4、#5、#23、#25、#31。

**负责人**：你确认产品与平台边界；Codex 完成技术核验和 ADR。

**阻塞**：无。

**阻塞后续**：全部。

**需要完成**：

- 使用正式抖音开放平台应用或沙箱账号列出当前可申请的数据、事件和动作能力；
- 为每项能力记录申请条件、授权作用域、额度、时效、Webhook/Poll、错误码和当前状态；
- 冻结计划级动作矩阵：`auto_allowed`、`review_required`、`blocked`；
- 冻结停止条件、勿扰、拒绝、频控、预算、内容和撤销规则；
- 输出 ADR，明确禁止非官方协议和规避检测。

**验收标准**：

- 能力矩阵由你确认，Codex 留存核验依据；
- 每项 UI 能力都能映射到真实平台能力或明确标注“不可用/待申请”；
- 未确认能力不会进入后端枚举和前端主按钮；
- 自动动作门禁有可测试的稳定原因码。

**开源参考**：`gtm-agents` 的 suppression/DNC 方法；不得用开源仓库替代官方能力验证。
