# AI 经营顾问前端打磨设计

## 背景

`#growth/agents` 已具备智能体团队总览、经营诊断报告、单智能体工作台、报表上传与多公司选择功能。现有 Growth E2E 基线为 8 个用例全部通过，但经营顾问内容区没有完整承接 GoodJob 深色产品外壳，卡片、报告、工作台和上传流程接近默认文档排版，不适合客户演示。

本次改造是保留式演进，不改品牌、信息架构、路由、后端协议或确定性分析规则。

## 目标

1. 让 AI 经营顾问四个主要界面与现有 GoodJob 深色指挥舱保持同一视觉语言。
2. 使企业健康评分、风险等级、数据来源和 90 天计划能够在演示中被快速理解。
3. 让报表上传、多公司选择和智能体问答具备明确、可用、可访问的交互状态。
4. 保持安全红线：不编造金额，不批准、发布或核销，税务只做风险体检，数字仍由确定性引擎计算。

## 非目标

- 不修复真实模式的登录重定向和 Growth API 401，这属于任务 C。
- 不修改经营诊断协议、报表解析规则或报告计算方法。
- 不新增成本明细、发票清单解析和知识库外部注入。
- 不替换 GoodJob 导航、字体或品牌标识。

## 视觉方向

设计解读：面向中小企业老板的 B2B 经营指挥舱，使用稳重、可信、中等信息密度的深色产品语言。

- 主题：全局深色，不在内容区切换浅色报告。
- 背景：近黑冷色背景，石墨色面板，低对比冷灰边框。
- 强调色：绿色只表达主操作、已选中和数据就绪。
- 语义色：红色表达高风险，琥珀色表达关注或校验警告。
- 形状：主面板圆角 16px，输入框和按钮圆角 10px，状态标签使用胶囊形。
- 层级：依靠间距、字号、边框和语义色建立，不使用蓝紫渐变、过度辉光或大面积玻璃态。
- 头像：六名智能体使用与概念图一致的独立 3D 卡通员工肖像。统一使用深墨绿背景、正面半身构图和柔和棚拍光线，并根据岗位通过人物、服装和配饰建立区分。网页使用 384 × 384 的压缩资源，卡片和工作台复用同一身份资产。

## 页面设计

### 智能体团队总览

- 保留标题、描述和“生成经营诊断报告”主操作。
- 顶部增加企业健康评分环和数据源状态区。评分使用 CSS `conic-gradient` 渲染，存在最近报告时显示 `healthScoreBps` 换算结果，尚未生成报告时显示“待生成”而不显示虚构分数。演示模式的 46 分来自现有 `demoDiagnosisReport()` 固定样例。
- 六名智能体使用同一卡片骨架，显示名称、角色、职责、能力、知识库、数据就绪状态和工作台入口。
- 六名智能体分别显示经营总管、财务、利润、成本、现金流和税务员工肖像；头像包含与角色名称对应的替代文本，不以头像代替名称或状态信息。
- 数据源徽章只显示真实已提供或已绑定的来源。无数据时显示“待配置”，不伪造就绪状态。

### 报表上传与多公司选择

- 使用两个同等权重的拖拽区承载资产负债表和利润表。
- 保留原生文件输入的表单能力，通过标签和键盘操作提供可访问的选择入口。
- 选择文件后显示文件名、类型和校验状态。不展示后端没有提供的文件尺寸、进度或精确时间。
- 解析完成后使用结构化公司列表。每行显示公司名、期间、状态和“查看诊断报告”。
- 单个公司解析失败时保留其行，用琥珀或红色行内说明呈现后端错误，不阻断其他成功公司。

### 经营诊断报告

- 顶部包含报告标题、公司、期间、数据源、健康评分环和一句经营摘要。
- 问题卡片使用风险色左边线，保持“原因、风险、建议”三段结构。
- 每个问题的证据使用原生 `details/summary` 折叠。页尾完整证据链也默认折叠，但不修改或省略原始内容。
- 90 天计划在桌面端使用水平时间轴，三个节点依次显示月份与动作。

### 智能体工作台

- 顶部保留智能体名称、角色和数据就绪状态。
- 桌面端使用三区布局：左侧职责与知识库，中间问答与结论，右侧可执行动作。
- 示例问题是可点击建议，点击只填充输入框，不自动提交。
- 分析输出使用“结论、判断依据、建议动作、证据”结构，不使用普通聊天气泡。
- 数据来源引用与结论同屏可见。不新增后端没有返回的置信度数值。

## 响应式与可访问性

- 桌面端内容容器遵循现有产品壳可用宽度，不覆盖或改动左侧导航。
- 900px 以下工作台三区收敛为单列，中间问答区优先。
- 768px 以下总览卡片和上传区收敛为单列，主操作占满可用宽度。
- 移动端报告的评分与摘要纵向排列，问题卡片保留语义边线，90 天计划转为纵向时间轴。
- 不出现水平滚动、文字裁切、按钮换行和低对比表单字段。
- 所有可交互元素具备可见焦点，移动端主要点击目标最小高度 44px。
- 评分环包含文本数值与语义标签，不依赖色彩传达分数。
- 风险等级同时使用文本和色彩。
- 所有新增动效只使用短时间颜色、边框、透明度和位移过渡，并遵循 `prefers-reduced-motion`。

## 组件与代码边界

- `src/growth/agents/view.ts` 继续负责纯 HTML 渲染。重复视觉结构拆成小型纯函数，不在视图中发起请求或保存业务状态。
- `src/growth/agents/controller.ts` 继续负责问题提交、报表选择、解析、公司选择和页面状态。
- `src/growth/styles.css` 提供限定在 `.agents-*`、`.agent-*`、`.diagnosis-report`、`.company-picker` 和 `.statements-*` 的样式。不新增全局标签选择器。
- `public/assets/business-advisor-agents/` 保存六张网页优化后的智能体员工肖像，源图由内置图像生成能力按概念图风格生成。
- 图标复用仓库现有 Phosphor 图标字体，不新增第三方依赖。
- 不修改 `src/growth/agents/api.ts` 公开协议，除非实施时发现现有类型不能表达已有合同数据。

## 数据流与状态

1. 总览页从现有智能体定义和最近报告状态渲染卡片、数据就绪和健康评分。初始真实模式没有最近报告时渲染“待生成”，演示模式则使用现有固定样例。
2. 用户选择两份报表后，控制器显示本地文件名并保持原有二进制上传流程。
3. 解析响应返回多公司结果后，视图依据每家公司的 `report` 或 `error` 渲染就绪行或错误行。
4. 用户选择成功公司后，控制器使用现有报告对象渲染诊断报告。
5. 工作台示例问题只更新表单输入，提交仍经过现有分析分支。
6. 报告和结论中所有数字来自 `DiagnosisReport` 或现有确定性辅助函数，不在 CSS 或视图常量中伪造。

## 错误与边界状态

- 未选择完整报表：上传面板内显示行内错误，保持用户已选的文件。
- 格式或解析失败：显示后端返回的可读错误，不转换成模糊的“未知错误”。
- 多公司部分失败：成功公司仍可查看报告，失败公司不显示可执行主操作。
- 无突出问题：报告使用专门空状态文案，不渲染空卡片。
- 智能体未知或数据待配置：保留现有错误语义，使用与整体界面一致的错误面板。
- 移动端长文字：卡片内容自然换行，不截断原因、风险、建议或证据。

## 验证策略

实施遵循红、绿、重构循环。

### 单元与视图测试

- 总览页包含健康评分语义、数据源区、六张顾问卡和主操作。
- 工作台示例问题具有可操作元素和稳定的 `data-*` 合同。
- 点击示例问题会填充输入框而不触发提交。
- 问题证据与完整证据链使用可访问的折叠语义。
- 报表选择后显示真实文件名，不改变原有提交数据。
- 多公司成功行和失败行具有不同的交互能力与语义。
- 报告风险等级、原因、风险、建议和证据内容完整保留。
